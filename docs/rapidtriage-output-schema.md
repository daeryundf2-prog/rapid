# rapidtriage output schema

This document freezes the current JSON output contract for `rapidtriage`.
When the CLI changes a field name, nested object, or filter semantics, update this file, the linked sample JSON files, and the related tests in the same change.

## Sample files

- `docs/samples/rapidtriage-manifest.sample.json`
- `docs/samples/rapidtriage-docs.sample.json`
- `docs/samples/rapidtriage-files.sample.json`
- `docs/samples/rapidtriage-extract.sample.json`

## Command overview

| Command | Default output file | Primary payload arrays |
| --- | --- | --- |
| `rapidtriage manifest ROOT` | `rapidtriage-manifest.json` | `providers[]`, `providers[].artifacts[]` |
| `rapidtriage docs ROOT -k KEYWORD` | `rapidtriage-docs.json` | `candidates[]`, `results[]` |
| `rapidtriage files ROOT` | `rapidtriage-files.json` | `candidates[]` |
| `rapidtriage extract INPUT_JSON OUTPUT_DIR` | `OUTPUT_DIR/rapidtriage-extract-manifest.json` | `entries[]`, `skipped[]` |

## `manifest` JSON

Top-level fields:

| Field | Type | Notes |
| --- | --- | --- |
| `generated_at` | string | Local ISO-8601 timestamp generated by the CLI. |
| `root` | string | Resolved scan root. |
| `platform` | string | `platform.platform()` string from the host running the command. |
| `keywords` | array of strings | Reserved for manifest contexts that also carry keyword search intent. The standalone `manifest` command currently writes an empty array. |
| `providers` | array | One row per provider returned by `rapidtriage.artifacts.all_providers()`. |

Provider object fields:

| Field | Type | Notes |
| --- | --- | --- |
| `name` | string | Stable machine-readable provider name. |
| `description` | string | Human-readable summary. |
| `target_platform` | string | `any` or platform-specific label such as `windows`. |
| `supported` | boolean | Whether the provider is supported on the current host / fixture. |
| `artifacts` | array | Provider-specific artifact rows. |

Artifact row fields:

| Field | Type | Notes |
| --- | --- | --- |
| `provider` | string | Provider name repeated on each row. |
| `artifact_type` | string | Stable machine-readable artifact family. |
| `path` | string | Filesystem path that the row describes. |
| `supported` | boolean | Mirrors row-level support state. |
| `details` | object | Provider-specific fields that must remain JSON serializable. |

### Windows artifact collector result shape

Current Windows-specific providers surfaced through `manifest`:

- `windows-browser-artifacts`
- `windows-recent-files`
- `windows-eventlog`
- `windows-registry`
- `windows-shellbags`

Current browser/recent `details` keys that appear in real collector output include:

- browser collector: `user`, `browser`, `profile`, `history_count`, `download_count`, `history[]`, `downloads[]`
- recent files collector: `user`, `entry_name`, `target_path`, `last_opened_at`, `evidence_type`
- placeholder providers: `note`

## `docs` JSON

Top-level fields:

| Field | Type | Notes |
| --- | --- | --- |
| `command` | string | Always `docs`. |
| `root` | string | Resolved scan root. |
| `generated_at` | string | Local ISO-8601 timestamp. |
| `summary` | object | Contains `candidate_count`, `match_count`, and `supported_extensions`. |
| `manifest` | object | Full embedded `manifest` payload for the same root. |
| `candidates` | array | Every document candidate considered by the scan. |
| `results` | array | Only candidates whose extracted text matched at least one keyword. |

`candidates[]` fields: `path`, `kind`, `size`, `modified_at`

`results[]` fields: `path`, `kind`, `matched_keywords`, `preview`, `size`

Current supported kinds: `txt`, `pdf`, `docx`.

## `files` JSON

Top-level fields:

| Field | Type | Notes |
| --- | --- | --- |
| `command` | string | Always `files`. |
| `root` | string | Resolved scan root. |
| `generated_at` | string | Local ISO-8601 timestamp. |
| `filters` | object | Echoes normalized filter values that shaped the result set. |
| `summary` | object | Contains scan counts plus oldest/newest matched timestamps. |
| `candidates` | array | Metadata-only candidate rows. |

`filters` fields: `categories`, `name_contains`, `path_contains`, `extensions`, `modified_after`, `modified_before`, `limit`

`summary` fields: `scanned_file_count`, `candidate_count`, `category_counts`, `newest_modified_at`, `oldest_modified_at`

`candidates[]` fields: `path`, `name`, `extension`, `size`, `modified_at`, `modified_epoch`, `categories`, `reasons`

Current built-in categories: `documents`, `archives`, `databases`, `executables`.

## `extract` JSON

Top-level fields:

| Field | Type | Notes |
| --- | --- | --- |
| `command` | string | Always `extract`. |
| `source_command` | string | Either `files` or `docs`, depending on the input JSON. |
| `input_json` | string | Path to the source JSON file used for extraction. |
| `root` | string or null | Root from the source payload when available. |
| `generated_at` | string | Local ISO-8601 timestamp. |
| `output_dir` | string | Extraction destination directory. |
| `filters` | object | Echoes normalized extract filters. |
| `summary` | object | Contains `input_count`, `selected_count`, `extracted_count`, `skipped_count`. |
| `entries` | array | Successfully extracted rows. |
| `skipped` | array | Missing/unreadable rows that were skipped. |

Common `entries[]` fields: `original_path`, `extracted_path`, `relative_path`, `sha256`, `modified_at`, `size`

Additional `entries[]` fields depend on `source_command`:

- from `files`: `categories`
- from `docs`: `kind`, `matched_keywords`

`skipped[]` currently contains `original_path` and `reason`.
