# AI coding-agent artifacts

Point the collector at a mounted or exported evidence directory containing the profile trees. Select a kind with the normal artifacts command.

```sh
python -m rapidtriage artifacts ./sample-evidence --kind codex-cli --output ./artifacts-codex-cli.json
```

The execution section of the evidence tree includes these kinds. Seizure, fraud, hacking and recovery runs schedule them.

| Kind | Evidence-relative paths | Records |
| --- | --- | --- |
| `claude-code` | `.claude/projects/**/*.jsonl`, `.claude/history.jsonl`, `.claude.json`, `.claude/settings{,.local}.json` | User and assistant text, tool use and results, working directory, model, typed prompt history with its project folder, and selected settings |
| `codex-cli` | `.codex/sessions/**/*.jsonl`, `.codex/history.jsonl`, `.codex/config.toml` | Replay messages, function and custom tool calls and results, turn model and working directory, prompt history and settings |
| `gemini-cli` | `.gemini/tmp/*/chats/*.json` or `*.jsonl`, `.gemini/tmp/*/logs.json`, `.gemini/settings.json` | Session messages, tool calls and embedded results, prompt logs and settings |
| `editor-chat` | `<editor>/User/globalStorage/state.vscdb`, `<editor>/User/workspaceStorage/*/state.vscdb`, `<editor>/User/workspaceStorage/*/chatSessions/*.json`, `<editor>/User/globalStorage/emptyWindowChatSessions/*.json` | Selected chat and composer JSON in SQLite `ItemTable` and `cursorDiskKV`, and VS Code chat session files |
| `agent-mcp` | The CLI settings above, project `.mcp.json`, `.cursor/mcp.json`, `.vscode/mcp.json` and editor `User/mcp.json` | One row per configured server with name, configured command and environment variable names |
| `herdr-sessions` | `.config/herdr/session.json`, `.config/herdr/session-snapshots/session-*.json`, `.config/herdr/session-backups/session-*.json`, the same below `.config/herdr/sessions/<name>/`, `.config/herdr/session-history.json`, `.config/herdr/herdr{,-client,-server}.log` and rotations, `.config/herdr/plugins.json`, `.config/herdr/config.toml`, `.local/state/herdr/agent-detection/status.toml` (Windows `AppData/Roaming/herdr` and `AppData/Local/herdr`) | Panes with workspace, tab, working folder, worktree, detected agent, the agent session ID or session file the pane reported, the launch and resume program and `--env-file` paths; recovery copies with the time herdr preserved them; pane screen history metadata (text only on request); pane spawn and exit, workspace, tab, session save and API events and warnings from the logs; installed plugins; storage-related settings; the last agent-detection rule check |

The editor may appear under Windows `AppData/Roaming`, macOS `Library/Application Support` or Linux `.config` in the evidence. The recognized product directories are Cursor, Code, Code - Insiders and VSCodium. Product directories can belong to any profile. Discovery matches path components below the evidence root only; the examiner's own home directory and environment are never consulted, and symbolic links that leave the evidence root are skipped. The collector reads a verified private SQLite snapshot, includes committed WAL content and queries only ordinary tables. A WAL, shared-memory or journal sidecar that is not a regular file, or a hot rollback journal, makes the database unreadable with a diagnostic instead of being followed or replayed. SQLite locators identify a table, rowid and key. Recognized keys include `bubbleId:*`, `composerData:*`, `composer.composerData`, `aiService.prompts` and selected workbench chat keys. Index-only or unfamiliar chat values can produce a diagnostic.

### herdr

herdr (github.com/herdrdev/herdr) is a terminal multiplexer for coding agents: workspaces hold tabs, tabs hold panes, and each pane runs a shell or an agent such as Claude Code, Codex or pi. It keeps its files in a config folder (`$XDG_CONFIG_HOME/herdr`, default `~/.config/herdr`, Windows `%APPDATA%\herdr`) and a state folder (`$XDG_STATE_HOME/herdr`, default `~/.local/state/herdr`, Windows `%LOCALAPPDATA%\herdr`). A debug build uses `herdr-dev`. A named session (`herdr --session <name>`) keeps its layout, recovery copies, screen history and logs in `sessions/<name>/` below the config folder. The collector matches these folders below a `.config`, `.local/state` or `AppData/Roaming`/`AppData/Local` component; folders moved by the XDG variables are not searched, and a folder that is only named `herdr` is not read. `agent` is `herdr-sessions`.

herdr records no conversation. The pane's agent session is the key to the other collectors: a Claude Code or Codex pane reports a session ID, which becomes the row's `session_id`; a pi pane reports its session file, given as `agent_session_file`.

- `agent-terminal-pane` (`session.json` and its recovery copies): one row per pane with `snapshot_kind` (`current`, `snapshot` or `backup`), `herdr_session` (`default` or the session name), `workspace_id`, `workspace_name`, `workspace_cwd`, `worktree_label`, `worktree_repo`, `worktree_checkout`, `linked_worktree`, `tab_name`, `tab_ref` (`w1:t2`), `pane_id` (herdr's internal number, the key in the file and in the logs), `pane_ref` (the public ID other tools such as dori use, `w1:p3`), `cwd`, the manual label as `text`, `focused`, `zoomed`, `terminal_agent` (the detected agent), `managed_agent`, `agent_session_source` and `agent_session_agent`, `session_id` or `agent_session_file`, the launch program (the first `launch_argv` entry) as `command_line`, `resume_agent` with the resume program as `resume_command`, and the paths given to `--env-file` in either argv as `env_files`. The other arguments are not exported: like MCP server arguments they can hold credentials without a label (positional keys, `-p<password>`, `-u user:password`) that redaction cannot recognise. The session the pane resumes is already in `session_id` or `agent_session_file`. `schema_version` is the file's `version` (3 at v0.9.5; a version 1-2 workspace without tabs is read as one tab). `session.json` records no time. herdr copies it to `session-snapshots/` (at most every 15 minutes when the layout changed, 48 kept) and to `session-backups/` (before replacing a layout it did not load, 3 kept); the copy's name holds the epoch nanoseconds and process ID at the time of the copy, given as `timestamp_utc` (to the microsecond) and `snapshot_pid`. The layout inside a copy was saved earlier than that. A name whose time is beyond what a date can hold keeps its row with an empty time and `timestamp-not-normalized`. File and folder names are compared without letter case.
- `agent-terminal-history` (`session-history.json`, written only with `experimental.pane_history`): one row per pane with `pane_id`, `line_count`, `char_count`, `text_sha256` (SHA-256 of the UTF-8 text with escape sequences removed) and `layout_fingerprint`, flagged `content-not-exported`. The scrollback belongs to every pane, shell panes included, so it can hold anything printed there (`cat .env`, keys without a label, case data); its text is exported only when the examiner asks for it with the collector option `pane_history_text` (`collector_options={"pane_history_text": True}`; the payload's `collector_options` records the choice). Then the whole text is redacted first and its last 8,192 characters, the most recent screen, are kept as `text`, so a secret across the cut does not leak. Workspace, tab and pane indexes follow the `session.json` saved with it. Escape sequences removed include CSI, OSC, DCS and similar strings, two-byte escapes such as `ESC 7` and `ESC ( B`, the 8-bit CSI and C0 and C1 controls.
- `agent-pane-spawned`, `agent-pane-exited` and `agent-terminal-event` (`herdr.log`, `herdr-client.log`, `herdr-server.log` and `.N` rotations): lines with a structured `event` and every warning or error, with `log_level`, `log_target`, `log_role` (`main`, `client` or `server`), the message as `text`, and `event`, `subsystem`, `outcome`, `pane_id`, `process_id`, `exit_status`, `workspace_id`, `tab_id`, `api_method`, `error` and `available_version` (an update herdr found) when the line has them. Other fields on the line, such as file paths, are not exported. Lines without an event below warning level are skipped.
- `agent-terminal-plugin` (`plugins.json`): `plugin_id`, `plugin_name`, `plugin_version`, `enabled`, `plugin_source_kind`, `plugin_repo`, `requested_ref`, `resolved_commit`, `plugin_root`, the description as `text`, and the install time.
- `agent-settings` (`config.toml`): the section names in `config_keys`, `resume_agents_on_restore`, `pane_history` and `worktree_directory`. Key bindings, themes and other values are not exported.
- `agent-terminal-update-check` (`agent-detection/status.toml`): the last check of herdr.dev for agent-detection rule updates (epoch seconds), its result as `text`, and `detection_agents` with each cached rule version. The downloaded rules in `agent-detection/remote/*.toml` are herdr's public catalog and are not read.

Sockets, lock files, plugin folders and herdr-managed worktrees (`~/.herdr/worktrees`) are not read. In the timeline, recovery copies are `layout-preserved`, pane spawn and exit are `started` and `ended`, other log lines `event`, plugins `installed` and the rule check `detection-checked`.

## Reading a row

`source_path` is relative to the evidence root. JSONL citations use a one-based physical line and zero-based byte offset. A whole JSON or TOML document starts at offset zero. Array indexes, project and server names distinguish entries within documents. SQLite rowids are logical locators.

Text messages, tool calls and tool results have distinct artifact types. An assistant message with text and two tool calls produces three rows. Structured tool arguments and patch headers supply referenced file paths. A call records a request to operate on a file. Any recorded result is a separate observation. Tool names can be associated with results by call ID within a session and file.

`timestamp_raw` preserves the source representation. `timestamp_utc` is ISO 8601 UTC with a `+00:00` offset. Text is normalized only when it is an RFC 3339 date-time with an explicit `Z` or `±HH:MM` offset (hours 00-23, minutes 00-59; an out-of-range offset such as `+01:60` is not rolled over); week dates, the basic format, a space separator and wall times without an offset are not guessed. Fraction digits are kept as recorded, padded to microseconds, so nanosecond digits are not rounded. Claude prompt history and editor values use integer epoch milliseconds and Codex history integer epoch seconds, converted exactly. Tool blocks can share the timestamp of their enclosing message. Embedded Gemini results share the recorded call time, which does not establish a separate completion time. The timeline uses only normalized evidence timestamps. A missing time stays empty. An ambiguous or invalid time carries `timestamp-not-normalized`. Missing session IDs, roles, models and paths stay empty.

`schema-version-not-validated` marks every row in this release. The input layouts have synthetic fixture coverage. A product version and a declared schema version are separate fields, copied only from the record that declares them (`version`, `cli_version`, `schemaVersion`, or a VS Code chat session file's `version`). When neither is recorded the row carries `version-unknown`; no version is inferred from field shapes. Gemini JSONL update and rewind records receive a diagnostic because reconstructing the final edited conversation requires replay. Codex user and assistant progress messages are compared with replay messages by role, exact text and occurrence count within the same turn of the same file. A turn starts at a `turn_context` record and is identified by its recorded `turn_id` (a context repeated with the same `turn_id` continues the turn); without one, each `turn_context` starts a new turn. A replay never stands in for a progress message of another turn. When one turn holds more progress copies of a message than replays, the earliest copies are paired and each remaining copy carries `replay-pairing-ambiguous`, because the source does not record which copy a replay duplicates. If a progress message is present, a second bounded pass counts up to 20,000 replay messages. Independent prompt history may document the same interaction.

## Bounds and privacy

| Scope | Limit and behavior |
| --- | --- |
| JSONL | 64 MiB prefix per source, 1 MiB per physical line including its delimiter. Oversized lines are drained in bounded chunks. Malformed UTF-8, malformed JSON and oversized lines produce cited diagnostic rows with a damage count. |
| Whole JSON or TOML | 8 MiB per document. Larger documents produce a diagnostic. |
| SQLite | 256 MiB for the database and sidecars combined, 2 MiB per selected value. Oversized inputs produce diagnostics. |
| Output | 20,000 rows per source and kind, then a limit diagnostic. Text fields hold up to 8,192 characters and lists up to 64 entries. Tool-name correlation retains up to 1,024 call IDs per source. |

MCP rows select server names, executable commands and environment variable names. Environment values, server arguments, headers and connection URLs are omitted. Every exported text field, including commands, file paths and tool results, passes redaction before it reaches a row: Rapid's URL credential redaction, the whole value of `Authorization`, `Proxy-Authorization`, `Cookie` and `Set-Cookie` headers in any scheme, credential assignments and option values (API keys, access and secret keys, tokens, passwords), bearer and basic credentials, private key blocks, JSON Web Tokens, AWS access key IDs and common token prefixes (`sk-`, GitHub, GitLab, Slack, Google, Hugging Face, npm). Arbitrary free text and command lines can still contain sensitive material without a recognizable label.
