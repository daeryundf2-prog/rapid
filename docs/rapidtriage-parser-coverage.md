# RapidTriage Parser Coverage Matrix

| Area | Status | Notes |
| --- | --- | --- |
| File metadata | Implemented | Names, paths, extensions, sizes, modified time, categories. |
| KAPE-style collect planning/export | Implemented baseline | `collect-plan` profiles preview present/missing Windows/macOS collection targets before heavy scanning or copying. `collect-export` can build a bounded source-relative export package with SHA256 copy logs. |
| Document text | Implemented | Text/log/config/data, EML/MBOX email, bounded Outlook MSG/PST/OST strings, PDF, Office OpenXML, and OpenDocument where dependencies support extraction. |
| Browser history/downloads | Implemented baseline+ | Chrome, Edge, Brave, Firefox local profiles; history/download fixture coverage; internet usage summaries, top-domain/category pivots, source hashes, browser-derived AI service usage detections, and browser-storage AI conversation candidates are normalized for Windows and macOS. |
| Recent files | Implemented baseline+ | Recent shortcuts parse Shell Link header/string fields for target path, working directory, arguments, timestamps, flags, hashes, and embedded path pivots; Jump Lists traverse recoverable OLE/CFB streams, promote Shell Link destination records with stream provenance, and fall back to embedded path extraction. |
| Timeline merge | Implemented baseline | Files, docs, artifacts, and normalized timeline export. |
| Case DB FTS | Implemented baseline | Documents and artifact metadata are indexed with SQLite FTS5; file metadata, timeline rows, review status filters, verification filters, and promoted artifact metadata filters are supported. |
| OCR | Partial | Depends on local Tesseract and image quality. |
| Image/media triage | Partial+ | Image dimensions, file hashes, perceptual average hash, similarity bucket, bounded inline thumbnail previews, and OCR queue hints are implemented for common image files. |
| Windows OS/account summary | Implemented baseline+ | User profile inventory plus `.reg` export hints for computer name, timezone, ProfileList SIDs, admin-group hints, last boot/shutdown timestamps, and exported account lifecycle fields such as created, last logon, password-last-set, disabled, and admin hints. Native SAM hive candidates now expose bounded account-name/RID key rows with offsets, hashes, last-write hints, and validation guidance; full SAM F/V attribute decoding remains planned. |
| Windows Event Logs | Partial+ | XML/JSON/JSONL/CSV exports from EVTX-oriented tools parse into normalized event/detection rows with hashes, categories, event/channel families, typed parameters, parser confidence, risk flags, reportability status, expanded built-in detections for high-value Windows/Sysmon/Defender/WMI/RDP behaviors, high-risk summary pivots, and EventRecordID gap hints; binary EVTX is inventoried and recoverable native record headers emit partial rows with timestamps, record IDs, file-header/chunk context, extracted strings, parameter candidates, and suspicious-term flags. |
| Registry hives | Partial+ | `.reg` exports parse into key/value rows including Run keys, suspicious persistence value hints, and USBSTOR device metadata. Native hive candidates such as `NTUSER.DAT`, `UsrClass.dat`, `SYSTEM`, and `SOFTWARE` are inventoried with `regf` header metadata, source hashes, sequence/dirty hints, last-write timestamp, bounded UTF-16 string pivots, bounded `nk`/`vk` cell candidate rows, and separate `registry-deleted-cell-candidate` rows for positive-size free/deleted key/value candidates; full key-tree reconstruction and deleted-value testimony still require validation with a dedicated hive parser. |
| MFT | Partial+ | MFT CSV/JSON/JSONL exports are normalized with record number, path, timestamps, and deleted hints; native `$MFT` files are inventoried with hashes, bounded FILE record-header samples, UTF-16 path pivots, and separate native `mft-record` rows for FILE header fields, in-use/deleted hints, base references, and nearby path strings. Full attribute decoding still requires a dedicated parser. |
| Zone.Identifier ADS | Partial | Exported `:Zone.Identifier`/`.Zone.Identifier` sidecar files parse ZoneId, referrer URL, and host URL. |
| Defender/Firewall/WER/Task Scheduler/WMI | Partial+ | Fixture-backed inventory for Defender MPLog, Windows Firewall W3C logs, WER reports, Task Scheduler XML, and WMI repository files; Task Scheduler rows promote hidden/run-level/start-boundary fields and suspicious command/user-writable-path risk flags, while WMI repository files include bounded string pivots for permanent event consumer/filter terms, commands, paths, URLs, and risk flags. |
| Prefetch | Partial+ | `.pf` inventory with executable hints, SCCA header detection, version hints, header executable-name extraction, best-effort common-version run count, last run timestamps, referenced path pivots, and separate `prefetch-reference` rows for review/search. Validate critical findings with PECmd or another dedicated parser. Execution-related registry export and PowerShell history imports are available through `windows-execution`, with a grouped execution summary for review pivots. |
| SRUM | Partial+ | SRUM CSV/JSON/JSONL/NDJSON exports can be normalized into app resource and network usage rows; direct `SRUDB.dat` is inventoried with ESE header metadata, hashes, bounded strings, path/URL pivots, suspicious-term flags, and separate `srum-database-pivot` rows so native app/URL candidates enter search, review, and execution grouping. Full SRUM table timestamp/counter decoding still requires a dedicated parser. |
| Windows Search EDB | Partial+ | `Windows.edb` is inventoried with ESE header metadata, hashes, bounded strings, path/URL pivots, export-tool guidance, and separate `windows-search-edb-pivot` rows for native indexed path/URL/text candidates; CSV/JSON/JSONL exports are normalized into searchable index entries with path, title, URL, extension, timestamps, and content snippets. Full ESE table decoding still requires a dedicated Windows Search parser. |
| Windows remote access | Implemented baseline+ | RDP files, Terminal Server Client cache files, and exported Terminal Server Client registry destinations are normalized for remote-access triage; cache files include bounded PNG/JPEG/BMP/DIB thumbnail signature pivots while full vendor-specific cache decoding remains planned. |
| Jump Lists/LNK | Partial+ | LNK header/string parsing and embedded path extraction implemented; Jump Lists are inventoried with OLE/custom hints, recover OLE/CFB stream listings, and promote embedded Shell Link destination records with stream provenance when present. Deep DestList MRU/account metadata decoding remains planned. |
| USN Journal | Partial+ | USN CSV/JSON/JSONL exports are normalized with FRN/parent/reason/timestamp fields; native `$J`/USN journal files are inventoried and recoverable v2/v3 records are emitted as triage `usn-record` rows with layout validation, reason/source/file-attribute flags, delete/rename hints, parser confidence, and validation warnings. |
| macOS user/browser/quarantine/TCC | Implemented baseline+ | User home inventory, Safari/Chromium/Firefox history imports with web/AI usage pivots, LaunchServices quarantine events, TCC privacy permission rows with high-value permission risk flags, LaunchAgent plist inventory, and bounded native pivots for Unified Logs, Spotlight stores, FSEvents files, and APFS snapshot hints are available through `macos-system`. |
| Linux system artifacts | Implemented baseline+ | User inventory, shell history, SSH authorized keys/known hosts, auth log events, auditd events, dpkg package/status events, Docker container configs, cron entries, and systemd service units are normalized through `linux-system` with source hashes and suspicious command/path risk flags. |
| A/B file compare | Implemented baseline | `compare` compares two individual files with MD5/SHA1/SHA256, field differences, bounded UTF-8 text diff previews, case bookmark support, and case-report review pivots. |
| Volume Shadow Copy compare/extract | Implemented baseline+ | `vsc-compare` compares current vs one or more snapshot folders and emits deleted/added/modified candidates with optional SHA256 confirmation; `vsc-extract` copies selected deleted/modified snapshot-side files into an evidence package with source/destination SHA256 values. VSC deletion command hints can also be surfaced from EVTX/PowerShell history imports. |
| Deleted-file carving | Implemented bounded baseline | `carve` scans files or mounted/exported folders for JPEG, PNG, PDF, and ZIP signatures with byte offsets, SHA256, caps, status, and optional extraction under analyst control. |
| Linux XFS | Direct-extract when tools support it | Image partition selection recognizes Linux/ext/XFS partitions before Sleuth Kit recovery; actual file recovery depends on the installed Sleuth Kit build's filesystem support. |
| Forensic containers AD1/L01/Lx01/AFF/AFF4 | Detection | UI/API adapter detection exists; direct parsing requires vendor/tool export first. |
| Raw/split images DD/RAW/IMG/001 | Direct-extract when tools exist | UI/API adapter detection plus `mmls`/`tsk_recover` recovery into the run output folder; split numeric segments are passed together when present. |
| Optical/archive images ISO/DMG/WIM/SWM | Direct-extract when tools exist | UI/API adapter detection plus `7zz`/`7z` extraction, with `bsdtar` fallback for ISO. |
| Virtual disks VHD/VHDX/VMDK/VDI/QCOW/QCOW2 | Direct-convert/extract when tools exist | UI/API adapter detection plus `qemu-img` conversion to raw and Sleuth Kit recovery; XVA remains vendor/export-first. |
| Memory dumps MEM/DMP/VMEM/VMSS/VMSN/HPAK | Detection + import+ | Memory dump detection exists; Volatility/Volatility3 JSON/JSONL outputs can be imported as process, network, cmdline, and malfind artifacts. Direct `.mem`, `.raw`, `.vmem`, `.vmss`, `.vmsn`, `.hpak`, `.dmp`, and memory-named `.bin` dumps receive bounded indicator scans for redacted BitLocker recovery-key candidates, suspicious strings, URLs, and IPs. |
| APK malware triage | Partial+ | Exported `.apk` files are inventoried with hashes, manifest metadata, permissions, dex/native-library counts, bounded suspicious string pivots, URL/IP indicators, and risk flags. |
| Memory forensics | Partial+ | Volatility-style output normalization is implemented; direct RAM dump scans now produce bounded BitLocker/string/network pivots, while full process reconstruction, key validation, and process-risk visualization remain long-term work. |
| Indicator and IOC summary | Implemented baseline | Completed run outputs can be summarized into URL, domain, IP, and hash pivots with source pointers and optional local `--rules` IOC matching; external TI API enrichment remains disabled/outside core. |
| AI prompt artifacts | Partial+ | Browser history detects common AI service visits such as ChatGPT, Claude, Gemini, Perplexity, Copilot, Poe, Hugging Face Chat, Grok, You.com, Phind, Mistral, DeepSeek, Meta AI, Character.AI, and Notion AI. Browser Local Storage, Session Storage, IndexedDB, and Cache files are scanned for role/content, prompt, question, answer, response, and completion snippets as review-only conversation candidates; full transcript completeness still requires service-specific validation. |
| Cloud export import | Partial | Google Takeout-style location/activity JSON and Apple/general account JSON exports are normalized with source hashes. |
| Mobile/cloud acquisition | Partial | Exported APK and cloud export imports exist; direct cloud acquisition/API collection remains deferred. |

Every new parser should publish:

- Stable parser ID and version.
- Input evidence type.
- Normalized output model.
- Fixture path and expected output.
- Known limitations.
