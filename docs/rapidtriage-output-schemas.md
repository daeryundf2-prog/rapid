# rapidtriage output schemas

This document pins the current JSON contract for `rapidtriage` outputs.

Regression coverage lives in `tests/test_rapidtriage_output_samples.py`, which generates fresh command output and compares it against the checked-in sample JSON under `docs/rapidtriage-output-samples/`.

## Placeholder conventions

The sample JSON uses a few placeholders so the examples stay stable across machines:

- `<ROOT>` — scanned fixture root
- `<GENERATED_AT>` — runtime timestamp generated by the command
- `<PLATFORM>` — host platform string from the runtime

### `commercial-readiness`

- Output: `rapidtriage-commercial-readiness.json` and `rapidtriage-commercial-readiness.md`.
- Top-level keys:
  - `command`
  - `generated_at`
  - `backlog_path`
  - `status`
  - `commercial_claim_allowed`
  - `release_claim`
  - `readiness_score`
  - `item_count`
  - `commercial_ready_count`
  - `non_commercial_count`
  - `status_counts`
  - `severity_counts`
  - `category_counts`
  - `maturity_gate_definitions`
  - `maturity_gate_summary`
  - `commercial_blocker_matrix`
  - `commercial_uplift_plan`
  - `validation_evidence_summary`
  - `priority_work_plan`
  - `all_items`
  - `critical_non_commercial_items`
  - `non_commercial_items`
  - `required_release_evidence`
  - `operator_guidance`
- Each row in `all_items` preserves the 120-item commercial parity backlog entry with `number`, `title`, `status`, `category`, `severity`, `remaining_gap`, `commercial_grade_ready`, `commercial_blockers`, `release_gate`, `maturity_gates`, `highest_maturity_stage`, and `next_required_gate`.
- `maturity_gates` always evaluates `implemented`, `usable`, `validated`, and `commercial_grade` in order. A higher gate must not be claimed until every earlier gate passes.
- `maturity_gate_summary` includes `next_gate_samples` and `next_gate_blocker_counts` so reviewers can see where work is blocked without reading all 120 items.
- `commercial_blocker_matrix` classifies every non-commercial item by one or more blocker lanes (`native-parser-depth`, `known-answer-validation`, `large-scale-performance`, `security-legal-assurance`, `platform-release-evidence`, or `external-operator-evidence`), separates internally actionable work from external/trusted evidence requirements, and exposes `top_internal_items` plus `top_external_evidence_items` for the next execution batch.
- `priority_work_plan` lists the next highest-priority backlog items with `current_stage`, `next_gate`, and `required_action`; use `--next-gate validated --limit 10` to focus JSON output on one maturity gate.
- `commercial_uplift_plan` selects the highest-priority non-commercial items, defaults to 70 goals, and splits them into five-item batches. Each goal includes `objective`, `implementation_track`, `acceptance_evidence`, `large_data_strategy`, `remaining_gap`, `external_evidence_required`, and `internal_next_step`. The plan-level `large_data_strategy` records the streaming, checkpointing, cursor API, virtualized UI, and benchmark proof expectations for large evidence sets.
- `validation_evidence_summary` is populated by `--validation-package`. Only passing known-answer datasets that explicitly name backlog item numbers can satisfy an item's `validated` gate; this never bypasses `commercial_grade` blockers.
- `--write-known-answer-template PATH` writes a not-run known-answer manifest template plus Markdown sidecar for the selected `--next-gate`/`--limit` items. The generated datasets include `backlog_items`, `required_assertions`, `reference_tools`, `minimum_evidence`, and `status: "not-run"` so validation evidence cannot be accidentally treated as passed.
- `--write-known-answer-template-dir DIR --template-items 1-120 --template-batch-size 5` writes 24 not-run template pairs plus `known-answer-template-batches.index.json/.md`, allowing the 120-item backlog to be validated in repeatable five-item batches.

### `vsc-compare`

- Output: `rapidtriage-vsc-compare.json`
- Top-level keys:
  - `generated_at`
  - `tool`
  - `current_root`
  - `snapshot_roots`
  - `options`
  - `summary`
  - `comparisons`
  - `notes`
- Each comparison includes `snapshot_root`, `snapshot_label`, a per-snapshot `summary`, and change `records`.
- Change records include `status` (`deleted`, `added`, or `modified`), `relative_path`, and `snapshot`/`current` file payloads with path, size, mtime, and optional SHA256.
- `case-db --import-vsc-compare` stores each change record as `vsc-deleted-file`, `vsc-added-file`, or `vsc-modified-file` artifact rows so they can be searched, reviewed, tagged, and included in reports.
- `case-search --metadata KEY=VALUE` can narrow artifact results by promoted metadata such as `event_id=4104`, `event_family=execution`, `channel_family=powershell`, `channel=Security`, `status=deleted`, or `snapshot_label=VSC1`.

### `compare`

- Output: `rapidtriage-compare.json`
- Top-level keys:
  - `command`
  - `generated_at`
  - `options`
  - `inputs`
  - `summary`
  - `results`
- Each result includes `comparison_id`, `status`, `timestamp`, `path`, `left_path`, `right_path`, `summary`, per-field differences, input descriptors, and a bounded unified text diff when both files are safe UTF-8 text under the configured byte cap.
- With three or more input files, `options.mode` is `multi`, `inputs.baseline` is the first file, `inputs.items` lists every file, and `results[]` contains one pairwise comparison from the baseline to each remaining file.
- `case` can bookmark `/results/<index>` rows from compare JSON, and `case-report` renders those reviewed rows under `A/B compare review pivots`.

### `search`

- Output: `rapidtriage-search.json`
- Top-level keys:
  - `command`
  - `generated_at`
  - `run_summary`
  - `keywords`
  - `options`
  - `summary`
  - `matches`
  - `ocr`
  - `analysis` unless `--no-analysis` is used
- Each match includes `source`, `kind`, `path`, `title`, `matched_keywords`, `preview`, `pointer`, `metadata`, and `search_match`.
- `options.search_mode` is `exact`, `fuzzy`, or `regex`; `search_match` records #61 matching mode, fuzzy distance where applicable, proximity-window result when requested, and validation-required status. `advanced_search_profile` records active mode, query validation including invalid-regex warnings, match-mode counts, proximity matched count, web/CLI controls, review warnings, and source-verification requirements. Top-level `core_accuracy_gates` records #61 query-mode, matching, proximity, pointer, and source-verification checks.
- `analysis.clusters` groups repeated hits by source, kind, extension, folder, and keyword, with representative match indices, #46 status, review hints, and `cluster_review_profile` so large searches can be triaged before opening every row.
- `analysis.clusters.cluster_review_profile` records family counts, high-volume cluster count, representative-first review queue, default `unreviewed`/`pending` review state, noise/report candidate hints, persistent-review-state blocker, and near-duplicate text/media clustering blocker.
- `analysis.entities` extracts bounded pattern/field-based people, account, email, phone, URL, domain, IPv4, and hash pivots linked back to match indices with #47 status, plus `entity_review_profile` for unreviewed entity queues, merge/split candidates, multi-source pivots, and analyst-verification blockers.
- `analysis.graph` emits capped nodes and cited edges for match-path-keyword-entity relationships for the web relationship view with #48 graph limitations, plus `graph_interaction_profile` for node/edge filter metadata, bounded edge-page metadata, source-citation coverage, and saved-layout/server-paging blockers.
- `analysis.timeline` extracts timestamp anchors from matched metadata and sorts them for quick chronological correlation with #49 validation warnings, plus `timeline_correlation_profile` for source/kind/timezone distributions, bounded event-page metadata, missing-timezone counts, and full-case join/clock-skew/cursor blockers.
- `analysis.deduplication` emits #60 duplicate groups with fingerprints, representative previews, representative hit indices, hidden duplicate counts, match indices, paths, source lists, duplicate/unique counts, candidate duplicate-resolution status, `dedup_review_profile` collapse-review metadata, and report-grade validation blockers.
- `analysis.workbook` creates draft hypotheses, review questions, next actions, and `workbook_review_profile` with hypothesis review queue, evidence attachment counts, edit/persistence/version-history blockers, and #50 status; it is a triage aid and must be verified against source rows and hashes.
- `analysis.core_accuracy_gates` emits #46~#50 and #60 gate objects showing which required clustering, entity, graph, timeline, workbook, and duplicate-hit checks are satisfied and which remain validation-required.
- `analysis.commercial_uplift_evidence` emits #46~#50 batch evidence with passed/failed validation IDs by item, search-analysis caps, truncation flags, report blockers, and explicit reminders that persistent review state, full-case reindexing, graph paging, timeline skew validation, and editable workbook versioning are not yet commercial-ready.
- Top-level search output emits #61 `commercial_uplift_evidence` with query mode, fuzzy/proximity options, result caps, passed checks, and blockers for multilingual relevance corpora, trusted query-hit manifests, query-builder validation, and measured FP/FN tuning.
- Case DB search output emits #51 `review_workflow_summary` with review/verification/assignee/priority counts, bounded review queue, report-candidate counts, active review filters, `core_accuracy_gates`, and blockers for role-based queues, notifications, multi-user conflict handling, and trusted review-audit diffs.
- Keyword-pack API output emits #62 `commercial_uplift_evidence` on each pack and on the library assessment with pack/keyword counts, provenance refs, deduplication state, and signed-pack/editor blockers. Completed-run search responses with `keyword_pack` parameters add `keyword_pack_selection_profile` with selected pack names, expanded keyword count, provenance refs, `core_accuracy_gates`, and selected-pack report-use warnings.
- Indicator summaries emit #63 `commercial_uplift_evidence` with offline TI feed refs, local-only/no-external-call controls, indicator/source caps, and signed/STIX/TAXII/confidence-decay blockers.
- Case DB report exports emit #64/#65 `commercial_uplift_evidence` on report citation and evidence-selection history managers with citation/history counts, source refs, selected-item controls, and exhibit-numbering/multi-user-signing blockers.

### `source-preview` API

- Endpoint: `GET /api/runs/{run_id}/source-preview?path=...`
- Common keys: `command`, `path`, `name`, `size`, `mime_type`, `download_url`, `metadata_url`, `search_url`, `viewer_actions`, `viewer_limitations`, `viewer_sandbox`, `viewer_metadata`, `review_workflow`, `compare_workflow`, and `preview_type`.
- Structured preview types include `text`, `image`, `sqlite`, `json`, `xml`, `email`, `media`, and `hex`.
- `viewer_sandbox` states #73 read-only bounded rendering, no content execution, active-content blocking status, external-network prohibition, byte/character caps, `preview-sandbox-policy-profile-v1` renderer/path policy metadata, and sandbox limitations.
- SQLite previews include #74 `large_sqlite_fts_optimization` metadata, `sqlite-preview-query-plan-profile-v1`, and an explicit optimization assessment so large tables stay bounded in the viewer while indexed case search handles broader review. Case DB optimization metadata includes `case-db-query-plan-profile-v1` head hashes for repeatable query-plan comparison.
- Review and compare viewer actions expose #51/#52 status fields plus `core_accuracy_gates` and `commercial_uplift_evidence` for reviewer, assignee, priority, due date, report inclusion, A/B/C pinning, and unresolved multi-user/specialized-diff blockers, but final report use still requires source verification.
- `compare` output includes #52 `compare_review_profile` with input inventory, comparison review queue, optional selection rationale, bounded review notes, note/rationale counts, and blockers for persistent compare notes plus binary/image/SQLite/timeline-aware semantic diff.
- Hex, SQLite, and email previews expose #53/#54/#55 `commercial_uplift_evidence` with passed viewer checks, byte/table/message caps, source refs, and explicit blockers for interactive jump UI, trusted offset validation, WHERE/deleted-row recovery, PST/OST/MSG conversations, attachment extraction, and report-citation export.
- Image and media previews expose #56/#57 `commercial_uplift_evidence` with gallery/transcript checks, thumbnail/perceptual-hash/cue/source-hash controls, and blockers for virtualized gallery review, playback/ASR execution, and selected evidence export.
- OCR queue and media-image rows expose #58/#59 `commercial_uplift_evidence` with queue counts, OCR/translation sidecar refs, language/confidence controls, and explicit blockers for native OCR execution, engine retry logs, Korean OCR calibration, and certified translation workflows. Image source previews also expose `ocr_queue_profile` and `korean_ocr_translation_profile`; `/source-ocr-queue` returns a bounded parent-folder `source-ocr-queue-page-v1` queue view, and `/source-ocr-translation` returns a bounded `source-ocr-translation-review-v1` side-by-side OCR/translation package with sidecar hashes, text hashes, quality metrics, and copy-safe citation text.
- `hex` previews are bounded read-only rows with `offset`, `offset_hex`, `hex`, `ascii`, `bytes_read`, `max_bytes`, `offset_navigation`, `range_citation_profile`, #53 `core_accuracy_gates`, #53 assessment, and `truncated`; `/source-hex-range` returns a bounded JSON citation package with range hashes, rows, and copy-safe citation text for a requested byte range. These outputs are for triage and byte-offset orientation, not a replacement for trusted source-file validation.
- `sqlite` previews include table profiles, schema SQL, column details, index hints, bounded rows, text-column search support, `table_page_profile`, #54 `core_accuracy_gates`, and #54 assessment. `/source-sqlite-table` returns `sqlite-table-page-v1` pages for a schema-validated table with `offset`, `limit`, optional `where_column` + `where_contains`, optional validated `order_by`, bounded rows, pagination metadata, and copy-safe row-page citation text; arbitrary SQL is intentionally rejected.
- `email` previews include bounded messages plus `threads` and `conversation_view` with `thread_id`, subject, participants, message order, date range, attachment counts, `attachment_package_profile`, #55 `core_accuracy_gates`, and #55 assessment. `/source-email-attachment` returns `email-attachment-package-v1` metadata with filename/content type/size/hash, copy-safe attachment citation text, and optional base64 content only under the bounded export cap.
- `image` previews include dimensions, thumbnails, perceptual-hash/similarity metadata, tag suggestions, `gallery_page_profile`, `ocr_queue_profile`, `korean_ocr_translation_profile`, OCR/translation sidecar status, #56/#58/#59 `core_accuracy_gates`, and report-selection guidance. `/source-image-gallery` returns `image-gallery-page-v1` bounded folder pages with image hashes, dimensions, thumbnail availability, similarity buckets, bucket counts, keyboard-triage metadata, and copy-safe image citation text.
- `media` previews include MIME type, bounded metadata, WAV duration/channel/sample-rate when available, #57 transcript sidecar rows, cue counts, sidecar hashes when bounded, `cue_package_profile`, #57 `core_accuracy_gates`, review-aid validation status, and explicit playback/transcript verification limitations. `/source-media-cue` returns `media-cue-citation-package-v1` records with cue timestamps, cue text hash, sidecar hash, optional source hashes, and copy-safe cue citation text.

### `ArtifactRecordV1`

- Schema: `rapidtriage/schemas/artifact-record-v1.schema.json`
- Producer: `rapidtriage worker-parse` and future Rust parser workers.
- Staging output: newline-delimited JSON, one `ArtifactRecordV1` object per line, with a sidecar manifest from the JSONL artifact store.
- Required forensic fields: `artifact_id`, `artifact_family`, `artifact_type`, `parser`, `parser_version`, `source`, `confidence`, `validation_required`, `commercial_grade_ready`, `commercial_grade_blockers`, `legal_limitations`, and `fields`.
- `source` preserves `case_id`, `source_id`, `source_path`, optional byte `offset`/`length`, and source hashes when available.
- The record is intentionally strict: parser workers must disclose confidence, validation requirements, and commercial-readiness blockers before rows can enter high-volume stores such as Parquet.

### `columnar-benchmark`

- Output: `columnar-benchmark.json`, `columnar-benchmark.md`, `artifact-records.jsonl`, and optional `artifact-records.parquet`.
- Top-level keys:
  - `command`
  - `generated_at`
  - `record_count`
