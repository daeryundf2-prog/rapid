# rapidtriage output schemas

This document pins the current JSON contract for `rapidtriage` outputs.

Regression coverage lives in `tests/test_rapidtriage_output_samples.py`, which generates fresh command output and compares it against the checked-in sample JSON under `docs/rapidtriage-output-samples/`.

## Placeholder conventions

The sample JSON uses a few placeholders so the examples stay stable across machines:

- `<ROOT>` — scanned fixture root
- `<GENERATED_AT>` — runtime timestamp generated by the command
- `<PLATFORM>` — host platform string from the runtime

## Samples

### `manifest`

- Sample: `docs/rapidtriage-output-samples/manifest-windows-artifacts.json`
- Top-level keys:
  - `generated_at`
  - `root`
  - `platform`
  - `keywords`
  - `providers`
- Each provider row includes:
  - `name`
  - `description`
  - `target_platform`
  - `supported`
  - `artifacts`

### `docs`

- Sample: `docs/rapidtriage-output-samples/docs-keyword-search.json`
- Top-level keys:
  - `command`
  - `root`
  - `generated_at`
  - `summary`
  - `manifest`
  - `candidates`
  - `results`
- `summary` currently records:
  - `candidate_count`
  - `match_count`
  - `supported_extensions`

### `files`

- Sample: `docs/rapidtriage-output-samples/files-default-scan.json`
- Top-level keys:
  - `command`
  - `root`
  - `generated_at`
  - `filters`
  - `summary`
  - `candidates`
- Each candidate row currently includes:
  - `path`
  - `name`
  - `extension`
  - `size`
  - `modified_at`
  - `modified_epoch`
  - `categories`
  - `reasons`

### `extract`

- Samples:
  - `docs/rapidtriage-output-samples/extract-from-files.json`
  - `docs/rapidtriage-output-samples/extract-from-docs.json`
- Top-level keys:
  - `command`
  - `source_command`
  - `input_json`
  - `root`
  - `generated_at`
  - `output_dir`
  - `filters`
  - `summary`
  - `entries`
  - `skipped`
- Common entry keys:
  - `original_path`
  - `extracted_path`
  - `relative_path`
  - `sha256`
  - `modified_at`
  - `size`
- Source-specific entry keys:
  - from `files`: `categories`
  - from `docs`: `kind`, `matched_keywords`

## Windows artifact collector rows

The `manifest-windows-artifacts.json` sample also fixes the current artifact row shape for:

- `windows-browser-artifacts`
  - `browser-history-downloads`
  - `browser-history`
- `windows-recent-files`
  - `recent-shortcut`
  - `jumplist-automatic`
  - `jumplist-custom`

Current browser rows carry `user`, `browser`, `profile`, `history_count`, `download_count`, `history`, and `downloads` under `details`.

Current recent/jumplist rows carry `user`, `entry_name`, `entry_hint`, `size`, and `modified_at` under `details`.
