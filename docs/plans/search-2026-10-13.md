## 0. 지금 검색의 실체와 결정

**지금**: 상단 바 전역 검색 한 칸 → `GET /api/runs/{id}/search?keyword=…`(`core/search.py run_unified_search`). 케이스 DB가 있으면 FTS5(unicode61) 후보 추림 + 파이썬 행 매칭, 없으면 JSONL 전수 스캔(20초 예산). 옵션은 exact/fuzzy/regex·출처·확장자·경로 포함·근접·known-good 숨김·키워드 팩. 결과는 최대 1,000건 한 페이지, 도메인 집계는 `source_counts` 다섯 개(documents/files/artifacts/web/timeline/indicators), 저장 검색은 케이스 DB `saved_search`(키워드+필터만). 시간·해시·IOC·신원·경로 글롭·레지스트리·이벤트 필드·위치 검색은 **없다**. 열 머리 필터와 필터 바는 "불러온 행 기준" 클라이언트 필터라 28만 행에서는 답이 아니다.

**왜 케이스 DB FTS를 그대로 키우지 않는가**: BSH 런의 케이스 DB는 이미 3.1 GB다(`artifact.data_json`이 출력 전체를 복제). unicode61은 한국어를 공백 단위로만 자르므로 "급여대장"은 찾아도 "급여"는 못 찾고, 시각·해시·필드 값 검색에는 색인이 없다. 스키마를 또 바꾸면 파서 라운드(W4가 케이스 DB 연결 키를 손보는 중)와 충돌한다.

**결정**:
1. **런별 검색 색인 `rapidtriage-search.db`**(런 출력 디렉터리, 케이스 DB와 별개, 언제든 지우고 다시 만들 수 있음). 한 테이블 `search_doc`에 모든 도메인의 행을 "문서"로 평탄화하고, FTS5 **trigram** 테이블(한국어 부분 문자열·대소문자 무시)과 시각/해시/필드/위치 보조 테이블을 둔다. 빌드는 P1 분석 실행기의 새 kind `search-index`(진행·취소·이력·재시작 복원 공짜). 런 완료 시 자동 제출, 분석(카빙·NTFS 메타·OCR·메모리)이 끝날 때마다 그 분석 행만 증분 추가.
2. **JSONL 스트리밍(`artifact_filter`)은 그대로**: 아티팩트 그리드의 유형/경로 필터는 색인 없이도 돌아야 하므로 유지. 검색 페이지는 색인만 쓴다. 색인이 없으면 검색 페이지가 "색인 만들기" 버튼을 보여주고, 전역 검색 칸은 옛 `GET /search`(스캔)로 **degrade**하되 상태줄에 "색인 없음 · 스캔 결과(부분)"를 쓴다.
3. **질의는 서버가 해석**한다. 칩 UI와 고급 질의문은 같은 문자열(§3.1 문법)로 수렴하고, 응답이 파싱 결과(`parsed.terms`)를 돌려주므로 저장 검색·URL·히스토리는 문자열 하나로 끝난다.
4. **검색 페이지는 탐색 단계의 `search` 뷰**다(레일 항목을 늘리지 않는다 — console-ia §3 "전역 검색 결과는 탐색 단계의 검색 결과 뷰로 연다"). 전역 검색 칸은 그 페이지로 들어가는 입구이고 `Alt+/`가 포커스를 준다.
5. 성능 목표(BSH 런 682636ce5605, 아티팩트 282,595 · 타임라인 280,272 · 파일 4,770 · 문서 1,637): 키워드 첫 페이지 < 2 s, 시간 창 < 1 s, 해시 1만 개 < 3 s, 색인 빌드 < 10 분, 색인 크기 < 1.5 GB, 검색 중 서버 메모리 증가 < 300 MB. 모든 질의는 벽시계 예산(기본 15 s)과 행 상한에서 멈추고 `truncated`+사유를 돌려준다. 500은 없다.

## 1. 최종 사용자가 보는 문제

검사관(국선·수사기관·기업 감사)이 BSH 이미지를 열고 하고 싶은 일은 이렇다.
- "'급여대장' 들어간 건 전부 — 문서 본문, 파일 이름, 폴더 열어본 흔적(ShellBags), 최근 문서, 카카오톡 메시지까지 한 번에." 지금은 문서·파일명은 나오지만 ShellBags 경로와 레지스트리 값은 안 나온다.
- "2025-05-28 저녁 7시 ~ 9시 사이에 이 PC에서 무슨 일이 있었나? 그 시각 전후 5분." 타임라인 28만 행을 그리드에서 스크롤하는 수밖에 없다.
- "이 해시 목록(수사기관이 준 300개) 중 이 PC에 있는 게 있나?" 없다.
- "4624에서 LogonType 10(RDP)인 로그온만, 사용자별로." EventData가 지금은 문자열이라 못 거른다(파서 라운드 W1 이후 가능).
- "SanDisk USB 시리얼이 언제 꽂혔나?", "AnyDesk.exe는 어디서 받았나?", "환자명 목록(200명)이 어느 문서에 몇 번 나오나?", "주민번호가 들어 있는 파일 수만 세고 값은 보이지 말 것."
- "이 결과를 통째로 '관련'으로 표시하고 CSV로 뽑아서 보고서 부록에 넣자. 나중에 같은 검색을 다시 돌리면 같은 결과가 나와야 한다."

## 2. 이상 상태

- **U-S-1 한 칸, 한 문법**: 상단 전역 검색에 `급여대장`을 치면 탐색 › 검색 결과 페이지가 열리고, 도메인별 건수가 칩으로 뜬다. 칩을 누르면 그 도메인만 남는다. 각 행은 스니펫에 일치 부분이 강조되고, Enter로 뷰어가 열리며 뷰어의 원본 검색에 같은 검색어가 들어간다.
- **U-S-2 질의 빌더 = 고급 질의문**: 칩 줄(키워드·시간·해시·IOC·신원·경로·레지스트리·이벤트·위치·리뷰)을 채우면 고급 입력에 `kw:"급여대장" AND time:[2025-05-28 .. 2025-05-30] AND in:eventlog`가 만들어지고, 반대로 고급 입력을 고치면 칩이 바뀐다. 문법 오류는 위치와 함께 한국어로 표시된다.
- **U-S-3 시간 검색**: 절대 범위, 상대 범위, 피벗(선택 행 ±5분), 시각 종류(생성/수정/접근/이벤트/실행/마지막 기록), 도메인/유형, 행위자(사용자·SID·컴퓨터)로 거르고, 결과 위에 히스토그램이 있다. 히스토그램 구간을 드래그하면 범위가 좁혀진다. "이벤트 없는 구간(≥ 6시간)"과 "업무 시간 외(22–06시, 런 시간대 기준)"를 토글할 수 있다.
- **U-S-4 해시 검색**: 해시를 붙여 넣거나(MD5/SHA1/SHA256 섞여도 됨, 1만 개) 해시 세트 파일(txt/csv/NSRL형)을 올려 세트로 등록하고, 파일·Amcache·브라우저 다운로드·카빙 결과·지표까지 일치 행을 본다. 세트는 known-good/known-bad/사용자 라벨을 달고, known-good 세트는 결과 숨김 옵션으로도 쓴다.
- **U-S-5 IOC 검색**: IP(CIDR), 도메인, URL, 이메일을 넣거나 STIX-lite CSV를 올려 EventData IpAddress·브라우저 방문·레지스트리·문서 본문·지표 후보에서 일치를 본다. 결과는 "후보"임이 표시된다.
- **U-S-6 신원 검색**: 사용자명·SID·로그온 ID·컴퓨터명·이메일·전화번호(한국 형식)·주민등록번호·계좌·카드 번호를 종류별로 센다. PII(주민·계좌·카드)는 **건수와 마스킹 미리보기만** 보이고, 검사관이 "값 보기"를 누르면 감사 기록이 남고 값이 보인다. 행 메뉴 "이 사용자가 한 일"을 누르면 그 사용자의 전 도메인 행이 시간순으로 나온다.
- **U-S-7 경로/파일 검색**: 글롭(`*\Downloads\*.exe`), 확장자 세트, 크기 범위, 시그니처 불일치만, 삭제된 파일만(NTFS 조인), 특정 폴더 아래만, 압축 파일 안의 항목, 문서 메타데이터(작성자/마지막 저장자/템플릿).
- **U-S-8 레지스트리·이벤트 검색**: 키 경로 글롭, 값 이름/데이터(REG_SZ 문자열, REG_BINARY 16진 부분 문자열), 마지막 기록 범위; 이벤트 ID 목록/범위, 제공자, 채널, EventData 필드=값(`data.LogonType:10`).
- **U-S-9 위치/미디어 검색**: GPS 경계 상자/반경, 카메라 제조사·모델, 촬영일 범위, 유사 이미지(pHash 해밍 거리 ≤ n).
- **U-S-10 리뷰 인지·교차 케이스**: 리뷰 상태/태그/메모 본문/북마크로 거르고, 같은 질의를 색인이 있는 다른 런들에 던져 런별 건수와 샘플을 본다.
- **U-S-11 저장·이력·내보내기·일괄 표시**: 저장 검색은 트리 "검색 결과" 아래 노드로 살아 있고(열면 재실행, 건수 배지), 최근 검색 50개는 되돌릴 수 있으며, 결과 전체를 "리뷰보드로" 보내거나 CSV/JSON(로케이터·해시·질의·색인 빌드 ID 포함)으로 내보낸다.

## 3. API 계약 (B가 구현, A는 이 계약으로 mock)

모든 응답은 JSON, 오류는 `{"detail": "<한국어 문장>"}`(옵션 검증은 P1과 같은 422 목록 모양). 모든 SQL은 파라미터 바인딩만 쓴다(글롭·정규식도 바인딩 값). 로케이터는 `^/(artifacts|candidates|events|indicators|results|rows|entries)/\d+$`만 받고, 검색 결과는 파일 경로가 아니라 로케이터로 뷰어를 연다.

### 3.0 색인 (`rapidtriage/core/search_index/`)

`<run output_dir>/rapidtriage-search.db`, `PRAGMA journal_mode=WAL, synchronous=NORMAL`, 읽기는 `mode=ro`.

```
search_meta(key, value)                      -- index_version, build_id, built_at, run_id, source_summary_sha256, tz
search_doc(
  doc_id INTEGER PRIMARY KEY,                -- 안정 ID(빌드 안에서 단조)
  collection TEXT, kind TEXT, locator TEXT,  -- 리뷰 맵과 같은 좌표 {collection, kind, locator}
  analysis_id TEXT,                          -- 분석 행이면 그 id, 아니면 ''
  domain TEXT, artifact_type TEXT,           -- domain = domains.ts의 16 도메인 키
  title TEXT, path TEXT, path_fold TEXT, ext TEXT, size INTEGER,
  ts INTEGER, ts_kind TEXT,                  -- epoch ms(UTC), created|modified|accessed|event|run|last_written|visit|download|taken|…
  actor TEXT, actor_sid TEXT, computer TEXT,
  md5 TEXT, sha1 TEXT, sha256 TEXT,
  text TEXT,                                 -- 검색 본문, 최대 64 KB
  fields_json TEXT,                          -- 필드 값(이름→값) 스니펫·칩 생성용, 최대 16 KB
  deleted INTEGER, sig_mismatch INTEGER, in_archive INTEGER, pii_count INTEGER
)
search_text USING fts5(text, path, title, content='search_doc', content_rowid='doc_id', tokenize='trigram')
search_field(doc_id, name, value_fold, value_int)   -- 인덱스 (name, value_fold), (name, value_int)
   -- name 예: eventid, provider, channel, data.LogonType, data.IpAddress, regkey, regval, regtype, author, last_saved_by, template, host, url, email, user, sid, logon_id, computer, phone, rrn(마스킹 해시), card(마스킹 해시), account, ip(value_int=IPv4 정수), archive_entry
search_hash(algorithm, value, doc_id)               -- 인덱스 (algorithm, value)
search_geo(doc_id, lat REAL, lon REAL, make, model, taken_ts INTEGER, phash INTEGER)
search_ident(doc_id, kind, value_fold, masked, hmac) -- 신원·PII 발생 위치. PII는 value_fold를 비우고 hmac(런별 비밀키, <run>/search/.pii-key)만 저장
인덱스: search_doc(ts), (domain, ts), (path_fold), (sha256), (actor), (computer), (artifact_type), (analysis_id)
```

**무엇을 text에 넣는가(도메인별 평탄화, `build.py`의 `flatten_<domain>()`)**: 이벤트 로그 = 렌더된 메시지 + EventData `이름=값` 전부 + 채널/제공자/컴퓨터/사용자; 레지스트리 = 키 경로 + 값 이름 + 디코딩 값(REG_BINARY는 16진 소문자 ≤ 4 KB와 UTF-16 추출 문자열); ShellBags/RecentDocs/UserAssist/LNK/JumpList = 복원 경로 + 대상 + 볼륨 시리얼; 실행 흔적(Prefetch/Amcache/ShimCache/BAM) = 실행 파일 경로 + 참조 경로(≤ 200개) + 해시; 브라우저 = URL + 제목 + 다운로드 대상 경로 + 참조자; 문서 = 제목 + 본문(64 KB) + 메타데이터(작성자·마지막 저장자·템플릿·회사); 파일 = 경로 + 이름 + 해시 + MIME; 메신저 = 메시지 본문 + 대화 상대; 미디어 = 경로 + EXIF 텍스트 필드. 타임라인은 **별도 문서로 만들지 않는다** — 시각은 각 원본 행의 `ts/ts_kind`로 들어가고, 한 행에 시각이 여러 개면 `search_doc` 행을 시각마다 복제하되 `locator`는 같고 `ts_kind`만 다르다(결과는 `locator` 기준으로 접고 `ts_kinds[]`를 붙인다). 분석 행은 `collection:"analysis", kind:<analysis_id>, locator:/rows/<n>`로 들어가고 OCR 텍스트는 그 이미지 문서의 text에 합쳐진다.

**빌드**: 분석 kind `search-index`(옵션 `{mode: "full"|"incremental", analysis_ids?: []}`; 단위 = 출력 파일/분석 1개; 500행마다 취소 확인; 결과 행 없음 — `summary {doc_count, by_domain, text_bytes, db_bytes, elapsed_s, skipped: {reason: count}}`). full은 `rapidtriage-search.db.building`에 만들고 끝나면 atomic replace(빌드 중에도 옛 색인을 읽는다). incremental은 `analysis_id`의 기존 문서를 지우고 다시 넣는다. 런 완료 시와 분석 완료 시 자동. 색인이 참조한 출력 파일의 (크기, mtime)과 `summary.sha256`를 `search_meta`에 두고, 바뀌면 `stale`.

**PII/신원 패턴(`patterns.py`)**: 주민등록번호 `\b\d{6}-?[1-8]\d{6}\b` + 검증 합 통과만; 휴대폰 `01[016-9]-?\d{3,4}-?\d{4}` 및 지역번호; 카드 13–19자리 Luhn 통과 + BIN 앞자리; 계좌는 은행별 길이표로 **후보**만; 이메일 RFC 간이; SID `S-1-5-21-\d+-\d+-\d+-\d+`; 로그온 ID `0x[0-9A-Fa-f]{1,16}`; 사용자명은 EventData TargetUserName/SubjectUserName, SAM 계정, `\Users\<이름>\` 경로 세그먼트에서만; 컴퓨터명은 EventData Computer, 하이브 ComputerName, LNK 호스트명에서만. 문서 하나당 최대 2,000회 발생까지 기록하고 넘치면 `pii_truncated`.

### 3.1 질의 문법 (`query.py`, 서버가 유일한 해석자)

```
query   := clause (sep clause)*            sep := "AND" | "OR" | 공백(=AND)
clause  := ["NOT" | "-"] atom
atom    := "(" query ")" | field ":" value | value          (field 없는 value = kw)
value   := "구절"  | /정규식/i? | [a .. b]  | 토큰
```
필드(칩 ↔ 필드 대응):
- 키워드: `kw:`(기본; trigram 부분 일치, 대소문자·NFC 무시), `word:`(단어 경계), `re:/…/`(정규식), `near:(a, b, 5)`(근접 n단어), `list:<목록 id>`(키워드 목록 OR 확장)
- 시간: `time:[2025-05-28 .. 2025-05-30T23:59+09:00]`(한쪽 생략 가능, 날짜만이면 그날 전체, 시간대 없으면 런 시간대), `time:[-7d .. ref]`(상대), `around:(<locator>, 5m)`, `tskind:(event, last_written)`, `in:(eventlog, registry)`(도메인), `type:(eventlog-event)`, `actor:`, `sid:`, `computer:`, `afterhours:true`, `gap:>=6h`
- 해시: `hash:<값>`(알고리즘 자동), `md5:` `sha1:` `sha256:`, `hashset:<id>`, `-hashset:<id>`(known-good 숨김)
- IOC: `ip:10.0.0.0/8`, `host:example.com`(`host:*.example.com` 하위 포함), `url:`, `email:`, `iocset:<id>`
- 신원: `user:`, `sid:`, `logon:`, `computer:`, `email:`, `phone:`, `rrn:*`(존재만; 전체 값이면 HMAC 비교), `card:*`, `account:*`
- 경로: `path:*\Downloads\*.exe`(글롭, `\`·`/` 동일), `ext:(exe, dll)`, `extset:(documents|executables|archives|images|scripts|config|db|email)`, `size:[1MB .. 10MB]`, `deleted:true`, `mismatch:true`, `archive:true`, `under:C:\Users\bsh\`, `author:`, `savedby:`, `template:`
- 레지스트리/이벤트: `regkey:HKU\*\Shell\BagMRU*`, `regval:`, `regdata:`, `regtype:REG_BINARY`, `eventid:(4624, 4634, 7045-7050)`, `provider:`, `channel:`, `data.<필드>:값`(정확 일치, `*` 접미 허용)
- 위치/미디어: `geo:bbox(37.4, 126.8, 37.7, 127.2)`, `geo:near(37.5665, 126.9780, 3km)`, `camera:`, `taken:[..]`, `phash:<16hex>~8`, `similar:<locator>~8`
- 리뷰: `review:(relevant, needs-review)`, `tag:`, `note:"…"`, `bookmark:true`, `analysis:<id>`

제약: 질의 길이 ≤ 4,000자, 절 ≤ 64개, 정규식 ≤ 512자·중첩 수량자·역참조 금지(400 "정규식이 너무 복잡합니다"), 정규식은 FTS 선행 리터럴로 후보를 먼저 줄이고 행 text에만 적용. trigram은 3자 이상이어야 색인을 타므로 1–2자 키워드는 `LIKE`(예산 적용, `warnings: ["2자 이하 검색어는 느립니다"]`). 모든 비교는 NFC+casefold.

### 3.3 기존 계약 변경
- `GET /api/runs/{run}/search`(v1)는 남긴다. 응답에 `deprecated: true`, `successor: "/search/query"`.
- **R7 기본값 변경(검색 지연)**: `analysis`·`ocr`·`detail` 기본 끔, `metadata=compact` 기본, `limit` 기본 250 + `offset` 페이지(`pagination.{offset, limit, returned, has_more, next_offset, total}`), 정규식은 고정 단어로 시작해야 함(아니면 한국어 422). 이전 응답이 필요하면 `analysis=1&ocr=1&detail=1&metadata=full&limit=500`(레거시 패널이 그렇게 부른다). 자세한 내용과 측정은 `docs/rapidtriage-known-limitations.md` "R7 검색 지연".
- `GET …/tree` 전체 보기 `search` 노드에 `index_status`, `saved_searches:[{id, name, last_count}]`.
- `GET /api/runs` 각 런에 `search_index_available`.
- 리뷰 맵/review-batch는 변경 없음.
- 분석 kind `search-index`가 처리 단계 카드에 나타난다("검색 색인" 카드: 상태·문서 수·크기·다시 만들기).

### 3.4 S1 구현에서 바뀐 점 (B1, 이유 포함)

- **FTS 한 열·`detail=none`**: `search_text`는 `text` 한 열(제목·증거 경로·본문을 합친 값)만 색인한다. 열 셋(`text, path, title`)·`detail=full`이면 BSH 크기 목표(1.5 GB)를 넘었다(첫 빌드 1.51 GB). 부분 일치는 `MATCH` 구절 대신 `LIKE '%…%'`로 묻는다(트라이그램 색인이 후보를 주고 SQLite가 재확인). `LIKE … ESCAPE`는 색인을 못 타므로 `%`·`_`가 든 검색어와 1–2자 검색어는 `instr(lower(text), ?)` 스캔(예산 적용, 경고)이다. (R7 S2: 색인 v3부터 비ASCII 2자 검색어는 `search_bigram` 표로 찾는다 — `docs/rapidtriage-known-limitations.md` `## R7 S2`.) 대소문자 무시는 ASCII 기준(SQLite `LIKE`/`lower`; 한글은 대소문자가 없다).
- **시각 복제 행**: 계획대로 시각마다 `search_doc` 행을 두되 복제 행은 `text`=NULL·`group_id`=원 행이고 FTS에는 원 행만 들어간다(색인 크기). 접기는 `locator` 대신 같은 값인 `group_id`로 한다. 시각 라벨은 `ts_kind`(대표)·`ts_labels`(같은 순간의 다른 라벨)·`ts_family`(created/modified/…)로 나눠 `tskind:`가 셋 다 본다.
- **본문 출처**: `rapidtriage-docs-index.json`은 본문을 저장하지 않는다(`stores_full_text: false`). 문서 본문은 케이스 DB `indexed_document.body`(64 KB)에서, 케이스 DB가 없으면 원본에서 다시 추출한다.
- **평탄화 범위**: 행이 2,000개를 넘는 유형은 압축 출력의 "행 고유 값"만 색인한다(유형 템플릿·파일별 문맥은 모든 행에 반복돼 색인만 키운다). 작은 유형(집계 행, USB 5행 등)은 전부. 검증·준비도·출처 보일러플레이트 키, ISO 시각, 긴 16진 다이제스트, 5자 이하 숫자는 색인하지 않는다. 컨테이너 경로(EVTX·하이브)는 `path:`/`under:`로만 찾고 본문에는 넣지 않는다. 행 상한은 문서·작은 유형·이벤트 로그 64 KB, 큰 유형 8 KB(리뷰 반영: 이벤트 4 KB → 64 KB). 잘림은 모두 센다(아래 "리뷰 반영").
- **`journal_mode=DELETE`**: WAL은 읽기 전용 열기(`mode=ro`)에 쓸 수 있는 `-shm`이 필요해 쓰지 않는다. 증분 갱신은 한 트랜잭션이다.
- **도메인**: `domain`은 트리와 같은 표(`core/artifact_domains.py`, `api/app/tree.py`에서 옮김)를 쓰고 파일=`filesystem`, 문서=`media`, 지표=`incident`. `in:`은 도메인과 컬렉션(`files|docs|artifacts|indicators|analysis`)을 모두 받는다.
- **S2 필드 일부 선반영**: `eventid:`·`provider:`·`channel:`(`search_field`)와 `data.<이름>:값`(본문의 `이름=값` 줄을 정확 일치, `*` 접미 허용)은 S1에 넣었다. 나머지 S2/S3 필드는 400 "…S2 단계에서 지원합니다".
- **`around:` 기준**: 로케이터만으로는 컬렉션을 알 수 없어 `<doc_id>` 또는 `<컬렉션>[:<종류>]/<로케이터>`(예 `artifacts:eventlog/artifacts/12`)를 받는다.
- **`time:` 끝 경계**: 표기한 정밀도까지 포함한다(`21:00` → 21:00:59.999). 날짜만이면 그날 끝까지.
- **정렬 `relevance`**: 색인 순서(문서 → 파일 → 아티팩트 → 지표 → 분석)다. FTS 순위는 `detail=none`에서 쓸 수 없다.
- **건수 상한**(리뷰 반영으로 바뀜): 집계 패스가 조건을 **한 번** 돌려 `temp.m`에 담고(최대 `TOTAL_CAP` = 1,000,000행, 메모리 보호) total·패싯·히스토그램·빈 구간·페이지를 모두 거기서 만든다. 상한을 넘으면 셋 다 처음 100만 행 기준(`total_exact=false`, `facets.exact=false`, `histogram.exact=false`)이고 페이지만 원 조건으로 계속 넘긴다(커서). 원 조건을 히스토그램용으로 다시 돌리지 않는다. `page.total_cap`은 1,000,000.
- **업로드**: `python-multipart`가 의존성이 아니어서 `/api/hash-sets`는 JSON `{name, label, lines}`, 표준 라이브러리로 푼 `multipart/form-data`(`file`·`name`·`label`), 원시 본문(`?name=&label=&filename=`)을 받는다.
- **자동 빌드**: 서버가 띄우는 앱(`rapidtriage.api.app:app`)만 런 완료 시 전체 빌드·분석 완료 시 증분 빌드를 제출한다(`create_app(auto_search_index=True)`; `RAPIDTRIAGE_SEARCH_AUTO_INDEX=0`이면 끔). 테스트·임베디드 앱이 임시 폴더에 빌드를 남기지 않게 하기 위함. CLI만 쓴 런은 `rapidtriage search-index <출력 폴더>`.
- **검색 이력**(리뷰 반영으로 바뀜): 첫 페이지 요청만 `<런 출력>/search/history.sqlite`의 `search_history` 표에 남긴다(커서 페이지는 같은 검색, 런마다 최근 500건만 유지). 쓰기는 백그라운드 스레드 하나가 모아서 한 트랜잭션으로 하므로 이벤트 루프를 막지 않고 케이스 DB 없이도 동작한다. `audit_event`에는 저장 검색 **생성**만 `search.saved.create`로 남긴다(§3.2 표의 "audit_event `search.run`"을 대체). 저장 검색은 여전히 케이스 DB가 없으면 409.
- **응답 추가 필드**: 행 `ts_local`·`flags`·`group_id`·`target_path`·`truncated`, `page.limit|sort|collapse|aggregates`, `facets.collection`, `histogram.tz|counts|exact|after_hours`, `index.tokenizer`, 질의 요청 `saved_id`(저장 검색 실행 시 건수 배지 갱신)·`aggregates`.

### 3.4.1 적대적 리뷰 반영 (S1 B2)

- **정규식(H1)**: 검사는 정규식 문자열이 아니라 파스 트리(`re._parser`)에서 한다(`core/search_index/regex_guard.py`). 400 "정규식이 너무 복잡합니다(…)": 32회를 넘는 반복(`*`·`+`·`{n,}`·`{n,40}`) 안의 가변 반복(깊이 무관: `(a+)+`, `((a+))+b`, `((\w+))+Z`), 그런 반복 안의 겹치는 선택지(첫 글자가 같거나 빈 선택지: `(a|b|ab)*c`)와 전후방 탐색(`(?=(a+))+b`), 반복을 품은 전후방 탐색, 역참조·조건 그룹, 같은 글자를 나눠 가질 수 있는 무한 반복이 세 개 이상 이어지는 것(`[a-z]+[a-z]+[a-z]+=`)과 **두 개라도 사이에 선택적 항목만 있는 것**(`\w+\w+`, `\w+\s*\w+` — 두 개만으로도 3제곱 시간이라 리뷰 기준보다 엄격하게 막는다; `\w+\s+\w+`·`.*a.*b`는 허용). 매칭은 SQLite 함수 밖에서 한다: FTS(또는 스캔) 후보를 파이썬으로 돌면서(`REGEX_CHECK_ROWS`=64행마다 예산 확인) 행당 64 KB까지, 384자 조각(128자 겹침, 가능하면 줄 끝에서 자름)으로 나눠 매칭하고 조각마다 행 시간 한도(50 ms)를 본다 — 한 번의 `re.search`가 384자를 넘지 않으므로 허용된 패턴의 최악도 조각당 수십 ms다. 한도를 넘은 행은 "확인 못 함"으로 세어 `truncated=true`와 경고를 낸다(일치 안 함으로 숨기지 않는다). 조각 경계를 넘는 128자보다 긴 일치는 놓칠 수 있다(문서화된 한계). 일치 위치는 스니펫에 그대로 쓰고 하이라이트도 같은 가드 매처로 짧은 창에서만 돈다. 질의 슬롯은 작업 스레드의 `finally`에서 반환한다(작업이 실제로 끝날 때까지 쥔다; 연결이 끊기거나 요청 태스크가 취소되면 취소 이벤트를 세운다).
- **히스토그램(H2·M1)**: 구간은 최대 `MAX_BUCKETS`=2,000개(정렬 경계 여유 2개 포함) — 넘으면 `ceil(폭/1,998)`초로 넓히고 경고. 파이썬은 2,000개 넘게 돌지 않고 집계는 SQL GROUP BY다. `collapse=true`면 구간·`ts_kind`·업무 시간 외 건수가 **그룹 수**(`counts:"groups"`), 아니면 행 수. 시간 창은 최상위 AND 조건일 때만 축을 자른다(`SanDisk OR time:…`은 자르지 않는다).
- **FTS 선행 리터럴(H3)**: 파스 트리에서 뽑는다(`\x44`·`\u…`·`\N{…}`·8진·`{,n}`·`(?x)`·`]`가 든 클래스 모두 파서가 처리). 범위 플래그 그룹(`(?i:…)`)은 건너뛰고, `i`(또는 `(?i)`)면 SQLite `LIKE`가 못 접는 글자(I·K·S: U+0130/U+0131/KELVIN/LONG S)와 대소문자가 있는 비ASCII 글자에서 끊는다. LOCALE이면 전체 스캔.
- **값 잘림(H4)**: 포렌식 페이로드 필드(ScriptBlockText, Payload, ContextInfo, CommandLine, ProcessCommandLine, ParentCommandLine, ImagePath, ServiceFileName, url, title, path, body; `_`·대소문자 무시)는 `VALUE_MAX_CHARS`(1,024) 대신 행 상한까지 통째로 넣는다. 이벤트 로그 행 상한 64 KB. EventData 값과 같은 `details` 값(`script_block_text`, `command_line`)은 한 번만 넣는다. 값·목록·행 본문 잘림은 모두 `summary.skipped`(`value-truncated`·`list-truncated`·`text-truncated`)와 `summary.skipped_fields`(사유별 필드별 건수, 상위 200)에 세고 행에 `truncated=1`, `summary.truncated_by_domain`. 키워드·정규식 질의는 일치 도메인(일치가 없으면 전체)에 잘린 행이 있으면 경고 "색인 상한에서 본문 일부가 잘린 행이 있어 그 부분은 검색되지 않습니다(eventlog N건 …)".
- **500 없음(M2)**: 괄호·NOT·`-` 중첩 32단계(400), 짝 없는 서로게이트(400; 본문 JSON 검증 오류도 422로), `around:` doc_id 12자리, 커서 정수 범위(±2^63)·키 길이, `size:` 20자리·2^62, 연도 9999 끝 경계, 시간대 오프셋 오류(400), 해시 세트 질의당 8개(400; ATTACH 한도 전), SQLite `OperationalError`/`OverflowError`는 한국어 400(잠김은 503), 손상 색인은 409.
- **색인 교체(M3)**: 질의는 요청마다 색인을 열고 바로 닫는다. 교체는 `SWAP_WAIT_SECONDS`(= 예산 15 + 유예 3 + 5 = 23초)까지 0.05→1초 백오프로 재시도하고, 실패하면 옛 색인을 두고 `.building`을 지우고 분석을 실패로 끝내며 `summary.status="build-failed-swap"`·`swap_error` — `GET …/search/index`도 `status:"build-failed-swap"`(옛 색인으로 질의는 계속 된다). 증분 갱신은 `busy_timeout` 25초로 독자를 기다린다. 읽기 연결은 5초 기다리고 메타 읽기는 3회 재시도해 잠깐의 잠금에 "none"을 내지 않는다. 읽을 수 없는 파일은 `status:"corrupt"`·`corrupt_reason`, 질의 409. 옛 형식(`search-index-v1`) 색인은 질의 409 "형식이 오래되었습니다", 증분 요청은 전체 빌드로 바뀐다.
- **`/…/`(M4)**: 정규식은 `re:/…/i?` 또는 `re:<패턴>`. 맨 `/…/`는 공백도 안쪽 `/`도 없고 경계에서 끝날 때만 정규식(`/usr/bin/ls`는 키워드). 필드 값(`path:/users/*`)의 `/`는 글자다.
- **대상 경로(M5)**: `search_doc.path2`(표시)·`path2_fold`(색인)에 LNK/Jump List 대상, Amcache·ShimCache·BAM 실행 파일(`\Device\HarddiskVolumeN`·`\VOLUME{…}`·`\\?\`·드라이브 문자 제거), Amcache 바로가기 대상, 다운로드 대상, Prefetch 실행 파일(참조 경로 중 실행 파일 이름과 같은 것)·참조 경로를 둔다. `path:`/`under:`는 둘 중 하나에 맞으면 일치. 행 응답 `target_path`.
- **리뷰 표시 5만 건(M6)**: 넘으면 경고, 리뷰 조건(`review:`·`tag:`·`note:`·`bookmark:`)을 쓴 질의는 `truncated=true`.
- **숨길 해시 세트가 지워졌으면(M8)** 경고하고 무시한다.
- **성능**: `aggregates:false`면 집계 패스 없이 첫 페이지만 — 최상위 AND 키워드(가장 긴 3자 이상 리터럴)의 FTS 순서(`rowid > :after ORDER BY rowid LIMIT 2000`)로 후보를 받아 행 모드 조건(상관 `EXISTS`, 서브쿼리 물질화 없음)으로 확인하고 `limit+1`에서 멈춘다(10청크 안에 못 채우면 집계 계획으로). 키워드가 없으면 조건을 `doc_id` 순으로 흘려 보낸다. `total`·`facets`·`histogram`은 `null`, `page.aggregates=false`; 커서는 두 모드에서 호환. `aggregates:true`(기본)는 위 한 번의 패스. `histogram`은 기본 `null`(요청하면 같은 패스에서). 커서는 실제 정렬(`es`)을 담는다(시간순→색인 순서로 바뀐 질의의 다음 페이지가 섞이지 않게).
- **기타**: 소문자 `or`/`and`/`not`은 검색어로 찾되 경고, `foo(`는 400(여는 괄호 위치), 길이 0인 `time:`/`around:` 창은 경고, 증분 빌드는 `summary.skipped`·`skipped_fields`를 합친다.
