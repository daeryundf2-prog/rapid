## 0. 적대적 리뷰의 결론(먼저 읽을 것)

1. **소유자의 의심은 맞다.** 실제 E01을 콘솔에서 끝까지 조작한 기록은 IMG-A 하나였고, 그 이미지는 수집기 31종 중 29종이 0행이다. 대부분의 화면은 0행 이미지나 합성 픽스처, 또는 같은 증거를 재처리한 S/Q에서만 "확인"됐다. 오늘의 IMG-B 전수 점검(스크린샷 579장)이 처음으로 행이 있는 데이터를 훑었지만 31% 추출본이고, 값의 정확성은 레지스트리 키 1개·SQLite 1개로만 대조했다. 메시지·이메일·USB·AI 행이 든 콘솔 처리는 아직 하나도 없다(GAP-046~058).
2. **지금 화면이 틀린 사실을 말하는 곳이 있다.** 재설계보다 먼저 고친다: 볼륨의 31%만 처리하고 "완료"(GAP-026·027), 실패한 단계를 "12/12 완료·오류 0"(GAP-029), 20초 예산에 끊긴 조회를 "행이 없습니다"(GAP-031), 잡음 2.3만 건을 "확장자 불일치"(GAP-040), 표시 5건인데 보고서 후보 0건이 될 수 있는 세 갈래 계산(GAP-012), 감정서 증거 표의 해시·경로 공란(GAP-009), 컨테이너 해시를 매체 해시와 비교하는 "해시 검증"(GAP-007).
3. **v1 계획의 약점**(이 문서가 고친 것): ① 수용 기준 다수를 합성 픽스처로 닫게 해 같은 실수를 반복할 구조였다(GAP-173) → "완료 = 실데이터 E2E" 게이트와 코퍼스 5종. ② "해시 검증 완료"를 와이어에 그렸지만 현재 구현은 그 말을 할 수 없다(GAP-168). ③ 딥링크·인용·testid 계약표를 쓰지 않고 "넘김 표 e2e"만 말했다(GAP-172) → 부록 D. ④ 레인 39개가 수일~주 단위라 병렬·검증 단위로 크다 → 4시간 이하 과제 127개. ⑤ 숨긴 85%가 검사관의 주 작업 대상인데 역할 기본값이 없었다(GAP-170) → 역할 모드. ⑥ 범위가 넓어(한국 수집기·의뢰 브리프·법률 내보내기·CLI 재편) 핵심이 늦어진다 → 범위 축소(D39).
4. **유지할 것**: 5단계 흐름의 뼈대(이름만 바꿈), 그리드+뷰어 분할과 키보드 흐름, 쓰기 전 고지, 출처 표기와 인용, 시간대 명시, 검토 이력, 비밀값 가림, 대화 보기, 접근성 기본기(이름·포커스), 해시 딥링크. 시각 감사·UX 감사·IMG-B 점검 모두 "골격은 살리고 위계·색 의미·용어·깨진 컴포넌트를 고치라"로 일치한다.

## 1. 사용자 정의

제품이 닿는 사람·시스템 여덟. 각자의 목표, 맥락, 오늘 RapidTriage로 하는 일(기록된 증거), 아픈 곳, "더 낫다"의 뜻.

### 1.1 분석 담당(검사관) — 도구를 돌리는 사람

- **목표**: 증거를 바꾸지 않고 빠짐없이 처리해, 변호사가 읽을 수 있는 상태로 넘긴다. 나중에 "무엇을 어떻게 했는가"를 설명할 수 있어야 한다.
- **맥락**: 로펌 포렌식 팀 1~3명. 사건당 증거 1~5개(PC·노트북·USB·모바일 추출본). 데스크톱 1920×1080 듀얼 모니터, 가끔 출장용 노트북 1366~1440. Windows·포렌식 도구(AXIOM·EnCase·FTK 계열)에 익숙, 명령줄 가능. 처리는 밤새 돌리고 아침에 확인한다. 기한 압박은 접수 당일~3일.
- **오늘 하는 일**(증거): 랜딩에서 케이스 만들기 3단계·입력 32개(UX 감사 §1) → 처리 143분 대기(IMG-B, speed) → 접수 대시보드 3.4화면을 스크롤 → 트리 366노드를 눌러 가며 확인(레지스트리 유형 노드는 14~20초, imgb-sweep D4) → 행에 R/I/X/B 표시·메모 → 보고서 6종 내보내기.
- **아픈 곳**: 20만 파일에서 멈춘 것을 화면이 말하지 않는다(GAP-026·027). 실패한 단계가 완료로 보인다(GAP-029). 건수가 화면마다 다르다(GAP-032). "미확정" 건수(GAP-033). 삭제 복구본이 NUL로 차 있는데 경고가 없다(GAP-041). 증거 폴더에서 CLI를 돌리면 증거 안에 쓴다(GAP-002).
- **더 낫다**: 처리 범위·실패·미실행이 숫자로 정직하다. 어떤 노드도 2초 안에 열린다. 숫자가 어디서나 같다. 내 손(단축키·트리·딥링크)은 그대로다.

### 1.2 변호사 검토자 — 읽고 판단하는 사람

- **목표**: 이 증거에서 무엇이 나왔는지 빨리 파악하고, 관련 자료를 골라 표시하고, 의견서·준비서면에 쓸 근거를 얻는다.
- **맥락**: 어소시에이트·파트너. 포렌식 용어를 모른다("런", "MFT", "아티팩트", "IOC"). 노트북 13~15인치(1280~1440), 회의 사이 20~40분 단위로 본다. Relativity류 리뷰 도구 경험은 있을 수 있다. 한글 입력 상태가 기본이다.
- **오늘 하는 일**(증거): 변호사가 직접 쓴 관찰 기록은 **없다**(UX 감사 한계, GAP-166). 감사가 모사한 과제에서 T1(1분 파악) 실패, T2(검색→태그) 3건에 40초, T5(보고서) 미리보기 없음. 접속은 검사관이 준 토큰 링크인데 토큰 화면에 안내가 없다(GAP-186).
- **아픈 곳**: 첫 화면이 사건이 아니라 처리 통계다(GAP-071). 제목이 증거 파일명이다(GAP-072). 검색 결과가 같은 파일을 여러 줄로 보여 준다(GAP-103). 보고 단계가 JSON 파일 52개 목록이다(GAP-120). 0건이 "없음"인지 "안 봄"인지 모른다(GAP-038). 영문·원시 키(GAP-090).
- **더 낫다**: 60초 브리핑, 12개 이하 범주, 문서 단위 검색, 한 건씩 읽고 키 하나로 판단, 내보내기 전에 보고서가 보인다. 모르는 말이 없다.

### 1.3 사건 책임자·파트너

- **목표**: 사건 방향을 정한다. "이 증거로 무엇을 주장할 수 있고 무엇은 못 하는가", "언제 끝나는가".
- **맥락**: 화면을 직접 조작하는 일은 드물고 회의실 화면·인쇄물·메신저로 받은 스크린샷으로 본다. 5분 안에 판단한다.
- **오늘**: 검사관의 구두 보고와 내보낸 PDF에 의존. 보고서에 처리 범위·한계가 없어(GAP-011) 한계를 모르고 판단한다.
- **더 낫다**: 브리핑 한 장(인쇄·공유 가능), 검토 진행률, 처리 제한이 첫 줄. 보고서에 한계가 자동으로 적힌다.

### 1.4 의뢰인 측 수령자(보고서 독자)

- **목표**: 보고서를 읽고 사내 결정(징계·고소·합의)을 내린다.
- **맥락**: 법무팀·인사팀·경영진. 도구를 쓰지 않는다. PDF·Word만 본다. 한컴·Acrobat·브라우저 뷰어.
- **오늘**: 보고서에 영문 절 제목·`status=`·"IOC/Indicator review pivots"가 나온다(GAP-122). PDF 한글 글꼴 미포함(GAP-023). 표가 세로선 문자다.
- **더 낫다**: 한국어만, 깨지지 않는 PDF, 근거마다 출처와 시각, 한계 절.

### 1.5 QA·검증 담당

- **목표**: "동작한다"는 주장을 실데이터로 확인하고, 증거가 바뀌지 않았음을 매번 증명한다.
- **맥락**: Sonnet 워커 + 사람 1명. Playwright·CLI. 실데이터는 Git 밖.
- **오늘**: 원시값 게이트가 실데이터 환경 변수 없으면 돌지 않는다(GAP-057). 수정이 vitest·TestClient로만 닫힌다(GAP-052). 감사 중 `taskkill`로 다른 e2e를 죽였을 수 있다(GAP-179). 코퍼스에 메시지·USB·AI 런이 없다(GAP-056).
- **더 낫다**: 코퍼스 5종, 번호 붙은 시나리오 105개, 물결마다 같은 회귀 묶음, 증거 스냅샷 자동 비교.

### 1.6 개발자(유지보수)

- **목표**: 화면 하나를 바꿔도 다른 것이 깨지지 않게, 빠르게 확인하고 병합한다.
- **맥락**: Opus 워커 다수 병렬 + 사람 1명. Python 3.12 FastAPI, React/Vite.
- **오늘**: testid·접근성 이름·문구에 테스트 1,559+90건이 묶여 있는데 계약표가 없다(GAP-149). 2,052줄 컴포넌트(GAP-150). 칩 3·빈 상태 4·메뉴 3(GAP-137). 분류 출처 5곳(GAP-087). 테스트 31분(GAP-152). 잠금 파일 없음(GAP-151).
- **더 낫다**: 계약표 + 계약 테스트, 종류당 컴포넌트 하나, 600줄 상한, 8분 사전 병합 묶음.

### 1.7 자동화·AI 에이전트(AX)

- **목표**: 사람 없이 처리·요약·검색·보고를 호출하고 결과를 기계가 읽는 형태로 받는다. 증거와 사용자의 화면을 건드리지 않는다.
- **맥락**: CLI·HTTP·Playwright. 오류를 문자열로 파싱할 수 없다.
- **오늘**: CLI 89명령 중 `--json` 77, `search` 없음, 종료 코드 체계 없음, `web`이 브라우저를 연다(GAP-145·178). API 태그 0·오류 봉투 없음(GAP-126·146). 사건 요약에 3종 이상 조합(GAP-144). GET이 파일을 쓴다(GAP-016).
- **더 낫다**: `/brief` 한 번, 한 봉투·한 오류 틀·종료 코드, `--read-only`, 숫자마다 `data-count`.

### 1.8 법원·상대방 감정인(산출물의 적대적 독자)

- **목표**: 보고서의 약점을 찾는다 — 증거가 바뀌지 않았나, 전부 봤나, 재현되나, 숫자가 맞나, 시각이 맞나.
- **맥락**: 보고서·해시 목록·감정서만 본다. 도구를 다시 돌려 볼 수 있다.
- **오늘 공격받을 곳**: 감정서 해시 표 공란·버전 미기재(GAP-009·010), 처리 범위 31% 미기재(GAP-011·027), 컨테이너 해시를 매체 해시처럼 표기(GAP-007), 내보내기 이력 덮어쓰기(GAP-014), 시간대 없는 생성 시각(GAP-015), A등급 규칙 참양성 0(GAP-044), "확장자 불일치 22,954건" 같은 잡음 수치(GAP-040).
- **더 낫다**(우리에게): 공격할 곳이 문서에 이미 "한계"로 적혀 있고, 나머지는 재현된다.

## 2. 사용 시나리오

로펌에서 흔한 사건 일곱 가지. 각 시나리오는 "오늘 막히는 곳(GAP)"과 "이상적 흐름(IS)"을 단계로 적는다. W5~W8의 Fable 리뷰는 이 시나리오를 그대로 걸어 본다.

### S-1 정보유출 내부조사(퇴사 예정자 PC)

1. 분석 담당이 E01 2개(데스크톱·노트북)로 새 사건을 만든다. 프리셋 "정보유출", 사건 키워드 5개. → 오늘: 입력 32개, 경로 오타로 고아 사건(GAP-076). 이상: 2단계·입력 5·폴더 선택기(IS-008).
2. 밤새 처리. 아침에 브리핑: 처리 범위 100%, 제한 2건, "먼저 확인할 것" B 6건. → 오늘: 31%에서 멈춘 것을 모름(GAP-026). 이상: IS-004·085.
3. 변호사가 링크로 들어와 60초에 파악: 주 사용 계정, 퇴사 2주 전 활동 급증, USB 5대, 클라우드 업로드. → 오늘: T1 실패. 이상: IS-001.
4. "반출 경로" → USB 탭: 장치별 최초·최종 연결·연 파일 수. 그 장치에서 연 문서 148건을 검토 묶음으로. → 오늘: USB가 3노드, 장치 묶음 없음(GAP-088). 이상: IS-030·040.
5. 하루 보기로 퇴사 전날: 14:01 문서 수정 → 14:03 열람(이동식) → 14:05 USB 연결. → 오늘: 5조작·3화면(GAP-114). 이상: IS-047.
6. 12건 "보고서 포함" → 미리보기 → 점검(메모 없는 3건) → PDF. → 오늘: 미리보기 없음(GAP-120). 이상: IS-056·062.
7. 상대방이 "삭제 파일은?" → 삭제·복구: 복구본 5만, 그중 내용 복구 불가 n건 구분. → 오늘: NUL 덤프(GAP-041). 이상: IS-023.

### S-2 근로·노무(근무 시간·업무 외 사용 다툼)

1. 프리셋 "근로·노무". 브리핑의 사용 기간·활동 시기 막대로 근무 패턴 확인. → 위험: 폴더 증거면 사본 시각뿐이라 틀린 기간(GAP-171). 이상: "산정 불가" 고지(IS-050).
2. 계정·로그온: 로그온·잠금 해제 시각을 날짜별로. 시간순에서 "업무 외 시간" 조건. → 오늘: 로그온이 이벤트 로그 아래 묻힘(GAP-083), 시각 표기 3종(GAP-116). 이상: IS-049.
3. 웹 › 방문·검색어로 업무 외 사용. 0건이면 사유(기록 삭제됨 vs 수집 실패). → 오늘: IMG-B 방문 0의 사유가 화면에 없음(GAP-038). 이상: IS-006.
4. 보고서에 표시 시간대(KST)와 시각 근거(로그온 이벤트 ID)가 자동 기재. → 오늘: 시간대 진술 없음(GAP-011).

### S-3 횡령(재무 담당자)

1. 사건 키워드: 계좌·송금·이체·상대 회사명. 키워드 팩 "금융". → 오늘: 기본 키워드 전부 영문, 팩 적중 미확인(GAP-107).
2. 검색 "계좌" → 문서 120건(한 파일 한 줄) → 묶음 → 한 건 보기로 키보드 검토. → 오늘: 중복 행·12자 미리보기(GAP-103). 이상: IS-031·041.
3. 개체 패널: 계좌번호·카드번호 후보. → 오늘: "Failed to fetch"(GAP-051). 이상: IS-037.
4. 엑셀·한글 문서의 최종 저장자·인쇄 시각(문서 메타). 보고서에 가림 처리된 계좌(뒤 4자리만) + "원문은 증거와 같다" 고지(IS-053).

### S-4 계약 분쟁(문서 작성·수정 시점)

1. 특정 계약서 파일명 검색 → 뷰어 "정보": 생성·수정·최종 저장자, 같은 파일의 다른 흔적(LNK·점프 목록·Office 최근 문서) "관련" 탭.
2. 시각이 취득 사본 시각인지 증거 시각인지 아이콘으로 구분(IS-050). → 오늘: 이탤릭으로만(GAP-117).
3. 타임스탬프 조작 의심 → 분석 담당 모드에서 NTFS 메타 실행. TSK 없으면 "부분 — 부트 섹터만"(IS-089). → 오늘: "완료"(GAP-036).
4. 인용 복사로 준비서면에 붙임. R7 때 붙인 인용도 계속 열린다(IS-015).

### S-5 가사(이혼 — 메신저·사진·위치)

1. 프리셋 "가사": 조건부 카드(사진·영상, 위치)가 본 목록으로 올라온다.
2. 메신저: 카카오톡 메시지 0건 → "신버전 DB는 읽을 수 없습니다 — 분석 담당자에게 요청(키 절차)"(IS-006). → 오늘: 사유 없음(GAP-158). 데스크톱 메신저 1,044건은 대화 보기로. → 오늘: 실데이터 대화 보기 미검증(GAP-049).
3. 사진: 썸네일 1.7만 장, 민감 사진 흐리게 기본. 깨진 이미지는 대체 글리프. → 오늘: 빈 사각형·콘솔 오류(GAP-097).
4. 위치: 좌표 행이 있으면 지도 대체 보기, 없으면 사유. → 오늘: 0행이 사람 표로 연결(GAP-081).
5. 의뢰인에게 나가는 보고서는 "내부 검토용"이 아니라 "법원 제출용" 프로파일(필드 최소)로.

### S-6 형사 변호 지원(수사기관 분석에 대한 반박)

1. 수사기관이 준 이미지 사본으로 처리. 첫 질문은 무결성: 취득 로그의 해시와 일치하는가. → 오늘: 컨테이너 해시를 비교해 거짓 불일치 가능(GAP-007). 이상: 매체 해시 대조(IS-069) **[승인 D34]**; 승인 전에는 "컨테이너 해시 계산됨 · 매체 해시 미대조"라고만 말한다.
2. "피고인이 그 시각에 PC를 썼는가": 계정·로그온 + 하루 보기 + 원격 접속 흔적. A등급 규칙이 떴다면 "검증 전" 표시 여부 확인(IS-124).
3. 감정서 초안: 도구 버전·규칙 버전·처리 범위·한계가 자동 기재, 증거 표에 해시·경로(IS-059·060). → 오늘: 공란(GAP-009).
4. 상대방 감정인이 재현할 수 있게 처리 이력 부록과 내보내기 감사 이력을 함께 낸다(IS-063·070).

### S-7 AI 도구 사용 조사(코드·문서 유출, 증거 인멸 의심)

1. "AI 사용" → 개요: 도구×계정×기간, 건드린 파일 상위 10, 파괴적 명령 B 6건. → 오늘: 답이 세 화면(GAP-118), 실데이터 콘솔 미검증(GAP-048).
2. 세션 → 대화 보기: 사용자 요청·도구 호출·파일 접촉. 키·토큰은 `[가림]`. → 오늘: 원본 탭 미가림(GAP-019).
3. 파일 접촉 → 그 파일의 다른 흔적(문서 메타·삭제 여부)으로 이동.
4. 흔적이 없으면 "로컬 흔적 없음 — 서버 측 기록 필요"와 수집 범위(4 GiB·최신 우선)(IS-054).
5. AX: 에이전트가 `brief --json`으로 AI 사용 여부를 읽고 `search --json`으로 후속 질의(IS-111·112).

## 5. 디자인 시스템과 화면 설계

전문은 [부록 C](r8/r8-design-system.md), 계약은 [부록 D](r8/r8-contracts.md). 방향 요약:

- **IA**: 전역 내비 4개(사건·살펴보기·검토·보고서) + ⚙(처리 이력·증거 관리·더 분석하기·산출물·설정). 처리 중에만 진행 띠. 상태바는 사건·증거·상태·시간대·연결.
- **역할 모드**: 검토자 모드(범주 12개 이하·6열·탭 4 이하) / 분석 담당 모드(기존 트리·헥스·SQLite·모든 조건·촘촘). 주소는 모드와 무관, 사용자별 기억(D30).
- **핵심 화면 12**: 진입(토큰·랜딩) / 사건 브리핑 / 살펴보기(목록+뷰어) / 검색 결과(문서 단위) / 하루 보기 / AI 개요 / 검토(묶음·한 건 보기) / 보고서(구성·종이 미리보기·제출 전 점검) / 새 사건·새 처리 / 처리 이력·더 분석하기·작업 센터 / 사람·장치 / 설정. 각 화면에 와이어·구성 요소·상태 5종(로딩·빈 상태·오류·부분·숨김 고지).
- **시각 언어**: 크롬 무채색. 색 4계열 분리(처리 상태 / 포렌식 상태 / 특이사항 등급 / 검토 판단), 항상 색+모양+글자. 빨강은 실패·무결성 불일치·A등급에만. 글자 7단(28/20/16/14/13/12/11), 이탤릭 금지, 고정폭 숫자. 4px 격자. 행 32(28·36). 기본 테마는 OS 따름.
- **컴포넌트**: 종류당 하나 — Chip, CountBadge, EmptyState, Skeleton, InlineAlert, Menu, Dialog, Button(4변형), Checkbox·Radio·Switch, Tabs, PageHeader, StatRow, ZeroReason, HiddenBanner, PartialBanner, TimeText, HashValue·PathText, Tree.
- **용어**: 한 개념 한 용어(부록 C.7). 분석 담당/검토자, 처리 n차, 사건, 먼저 확인할 것·특이사항, 검토·관련 있음·재검토·제외·보고서 포함, 범주, 항목, 출처, 조건, 목록. lint로 강제.

## 9. 1:1 검증 절차

목표: 구현이 끝난 화면이 이상적 상태 125문장과 **하나씩** 같다는 것을 증거로 보인다. 다르면 예외 없이 다시 계획한다.

### 9.1 추적표

[부록 G](r8/r8-traceability.md): IS → GAP → 과제 → QA → 판정. 부록 A·B·E·F에서 기계적으로 생성한다(작성 시점 검사: GAP 없는 IS 0, 과제 없는 IS·GAP 0, QA 없는 IS 0). `scripts/r8-trace-audit.py`(T-003의 일부)가 물결마다 다시 만들고 구멍이 있으면 실패한다.

### 9.2 판정 규칙

| 판정 | 조건 |
|---|---|
| **일치** | 그 IS의 QA가 전부 실데이터에서 통과했고, 증거(스크린샷·JSON·파일 경로)가 추적표에 연결돼 있고, Sonnet 재실행과 Fable 확인이 끝남 |
| **불일치** | QA 하나라도 실패, 또는 통과했지만 Fable이 IS 문장과 다르다고 판단(QA가 문장을 덜 덮음) |
| **미검증** | 대상 데이터가 없어 실행 불가. 부록 E.5의 사유 목록에 있을 때만 허용하고 known-limitations·릴리스 노트에 적는다. 합성만 통과는 "미검증"이다 |

"거의 됐다", "다음에", "환경 문제"는 판정이 아니다. 수치 기준은 반올림하지 않는다(2.0 s 기준에 2.1 s는 실패).

### 9.3 서명

- 과제: 구현자(Opus)가 아닌 세션(Sonnet)이 수용 검사와 검증 명령을 처음부터 다시 실행한 로그.
- 물결: Fable이 (a) diff 전체, (b) 추적표의 해당 행, (c) 2절 시나리오를 걸어 본 기록, (d) 증거 스냅샷 diff를 보고 S1·S2 0을 확인. 발견은 GAP-191 이후로 등록.
- 릴리스: 소유자. 추적표 판정 열, 미검증 목록, 사람 테스트 결과, 엔지니어링 기준선과 릴리스 증거의 구분(AGENTS.md)을 받는다.

### 9.4 불일치가 나오면(재계획 루프)

1. Fable이 불일치를 GAP으로 적는다(증거·IS·심각도).
2. 원인을 셋 중 하나로 가른다: 구현 결함 / 과제 누락(계획 결함) / IS 문장이 틀림(이상 정의 결함). 셋째는 소유자 결정 없이는 IS를 고치지 않는다.
3. 4시간 이하 과제로 쪼개 다음 묶음에 넣는다(파일 배타 규칙 그대로). 같은 IS가 두 번 불일치하면 그 영역의 설계를 다시 검토한다(부록 C 해당 절 개정).
4. 고친 뒤 그 IS의 QA **전부**와 회귀 묶음을 다시 돌린다(실패한 QA만 재실행 금지).
