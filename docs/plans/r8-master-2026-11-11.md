계획·적대적 리뷰: Fable 5.2(코드베이스 소유자·수석 계획). 구현: Opus(과제별 워크트리). 검증: Sonnet. 병합은 CI 초록 + 사업 소유자 지시 때만.
이 문서가 R8의 **활성 계획**이다. v2(2026-11-11)와 v1(`docs/plans/r8-redesign-2026-11-11.md`)을 대체한다. 파일 이름은 링크 호환을 위해 그대로 둔다.

방식(그대로 따름): 사용자를 정하고 상상한다 → 이상적 상태를 이유와 함께 정의한다 → 현재와의 차이를 전부 나열한다 → 계획과 QA 시나리오를 타협 없이 세운다 → 구현 뒤 이상적 상태와 1:1로 확인하고, 다르면 예외 없이 다시 계획한다. 작업은 작은 quick 과제로 잘게 쪼개 병렬로, 검증은 더 엄격하게.

## 0. 결론 먼저

1. **사업 소유자의 의심은 맞았고, 생각보다 깊다.** 실제 E01을 콘솔에서 끝까지 조작한 기록은 IMG-A 하나였고 그 이미지는 수집기 31종 중 29종이 0행이다. IMG-B 전수 점검이 처음으로 행이 있는 데이터를 훑었지만 값의 정확성은 2건만 대조했다. 메시지·이메일·USB·AI 행이 든 콘솔 처리는 아직 없다. 여기에 더해 **CI가 초록이었던 적이 최근 60회 동안 없고**, 프런트 테스트는 CI에서 돈 적이 없으며, e2e는 다른 워크트리의 서버에 붙어 "통과"할 수 있었다(GAP-209~212).
2. **계획 자신이 틀린 사실을 화면에 넣으려 했다.** v2의 "볼륨의 31%만 처리"는 할당 파일과 삭제 레코드를 한 분모에 섞은 숫자였다. 올바른 문장은 "할당 파일 목록화 약 100% · 삭제 레코드 48.7만 중 5.5만(약 11%)만 내용 시도 · 43만 미시도 · 삭제 디렉터리 27.3만 미목록 · 파티션 1/2"이고, 이것도 `fls` 대조 전까지는 강한 추정이다(GAP-026·358). 그래서 범위는 **네 축**으로 말하고, 대조 도구가 없으면 "추정"이라고 쓴다.
3. **지금 화면·산출물이 틀린 사실을 말하는 곳**(WB가 닫는다): 실패한 단계를 "12/12 완료·오류 0"(GAP-029), 예산에 끊긴 조회를 "행이 없습니다"(GAP-031), 잡음 2.3만 건을 "확장자 불일치"(GAP-040), 표시 5건인데 후보 0건이 될 수 있는 세 갈래 계산(GAP-012), 감정서의 해시 표 공란과 **키를 고쳐도 틀린 표**(추출 사본 해시, GAP-009·294), 매니페스트 시각을 "인수 시각"으로(GAP-295), 컨테이너 해시를 매체 해시처럼 비교(GAP-007), 캐시 해시를 "원본 무결성"으로(GAP-290), 결과 폴더 경로를 "원본 경로"로(GAP-335), 본문을 수집하면서 "메타만"(GAP-319), 브라우저에 방문이 있는데 "챗봇: 로컬 증거 없음"(GAP-329), 추출한 날의 시각을 "수정 시각"으로(GAP-246 — 표식은 WB, 근본 수정은 승인 뒤).
4. **새는 곳**(병합된 보안 레인의 독립 검증 + WB): 자격 증명 파일 본문이 다운로드로 나온다(GAP-308), API 한 번으로 임의 폴더를 지울 수 있다(GAP-004), 가져온 요약 파일이 읽기·쓰기 위치를 정한다(GAP-291), GET 7경로가 쓴다(GAP-016), 원격 모드가 평문이다(GAP-309).
5. **v2 설계의 약점**(이 문서가 고친 것): 분석 담당의 키와 주소를 바꾸려 했다(GAP-351) · 화면을 두 벌로 유지하려 했다 · 변호사 노트북(1280×720)에서 잘리는 와이어(GAP-352) · 표시할 때마다 분모가 움직이는 검토 묶음(GAP-354) · 브리핑이 과제 70개 뒤(GAP-355) · 기존 출력과 충돌하는 CLI 봉투(GAP-231) · 엔진을 맨 끝에 · AI는 화면 통합뿐이고 깊이·정확성·코퍼스가 없음 · 감시연속성 입력을 미룸.
6. **유지할 것**: 5단계 흐름의 뼈대와 주소, 그리드 + 뷰어 분할과 키보드 흐름, 쓰기 전 고지, 출처 표기와 인용, 시간대 명시, 검토 이력, 비밀값 가림, 대화 보기, 접근성 기본기, 인증(헤더 토큰·`compare_digest`·Host/Origin 허용 목록), 자격 증명 값 0 정책, 어댑터 격리, "부재 ≠ 미사용" 갭 표. 감사 넷(UX·시각·IMG-B·소유자 실화면)이 모두 "골격은 살리고 위계·색 의미·용어·깨진 컴포넌트를 고치라"로 일치한다.

### 1.1 분석 담당(검사관) — 도구를 돌리는 사람

- **목표**: 증거를 바꾸지 않고 빠짐없이 처리해 변호사가 읽을 수 있는 상태로 넘긴다. 나중에 "무엇을 어떻게 했는가"를 설명할 수 있어야 한다.
- **맥락**: 로펌 포렌식 팀 1~3명. 사건당 증거 1~5개. 데스크톱 1920×1080 듀얼 모니터, 가끔 출장용 노트북. Windows·포렌식 도구에 익숙, 명령줄 가능. 처리는 밤새 돌리고 아침에 확인한다. 기한 압박은 접수 당일~3일.
- **오늘 하는 일**: 랜딩에서 사건 만들기 3단계·입력 32개 → 처리 143분 대기(진행률 없는 62분짜리 단계 포함) → 접수 대시보드 3.4화면 스크롤 → 트리 366노드(레지스트리 유형 노드는 14~20초) → R/I/X/B 표시·메모 → 보고서 6종.
- **아픈 곳**: 삭제 레코드 43만 건이 목록에도 없는 것을 화면이 말하지 않는다. 실패한 단계가 완료로 보인다. 건수가 화면마다 다르다. 파일 수정 시각이 처리한 날이다. 밤샘 처리가 끝났는지 탭을 눌러야 안다. 증거 폴더에서 CLI를 돌리면 증거 안에 쓴다. 62분짜리 추출이 중단되면 처음부터다.
- **더 낫다**: 범위·실패·미실행이 숫자로 정직하다. 어떤 목록도 2초. 숫자가 어디서나 같다. 손(단축키 33개·주소·팝아웃·트리 순서)은 그대로다. 탭 제목만 봐도 끝났는지 안다. 첫 브리핑이 15분에 나온다(승인 뒤).

### 1.2 변호사 검토자 — 읽고 판단하는 사람

- **목표**: 이 증거에서 무엇이 나왔는지 빨리 파악하고, 관련 자료를 골라 표시하고, 의견서·준비서면에 쓸 근거를 얻는다.
- **맥락**: 어소시에이트·파트너. 포렌식 용어를 모른다. 노트북 1920×1080에 배율 150%(CSS **1280×720**), 회의 사이 20~40분 단위로 본다. 한글 입력 상태가 기본이다. 분석 담당이 보낸 토큰 링크로 들어온다.
- **오늘 하는 일**: 변호사가 직접 쓴 관찰 기록은 **없다**(GAP-166). 모사한 과제에서 T1(1분 파악) 실패, T2(검색 → 태그) 3건에 40초, T5(보고서) 미리보기 없음.
- **아픈 곳**: 첫 화면이 사건이 아니라 처리 통계다. 모든 제목이 폴더 약칭이다. 검색 결과가 같은 파일을 여러 줄로 보여 준다. 읽는 화면이 13px 격자다. 어디까지 봤는지 표시가 없다. 보고 단계가 JSON 52개 목록이다. 0건이 "없음"인지 "안 봄"인지 모른다.
- **더 낫다**: 교육 없이 쓴다. 60초 브리핑, 12개 이하 범주, 문서 단위 검색, 읽기 좋은 본문(15px·72자), 한 건씩 키 하나로 판단, 구절을 인용으로 복사, 내보내기 전에 보고서가 보인다. 모르는 말이 없다.

### 1.3 사건 책임자·파트너

- **목표**: "이 증거로 무엇을 주장할 수 있고 무엇은 못 하는가", "언제 끝나는가".
- **맥락**: 회의실 화면·인쇄물·메신저로 받은 스크린샷으로 본다. 5분 안에 판단한다.
- **오늘**: 구두 보고와 PDF에 의존. 보고서에 처리 범위·한계가 없다. 공유받은 스크린샷에 사람 이름이 든 경로가 그대로 있다.
- **더 낫다**: 브리핑 한 장("화면 공유용 보기", A4 1쪽), 검토 진행률, 범위와 한계가 첫 줄.

### 1.4 의뢰인 측 수령자(보고서 독자)

- **목표**: 보고서를 읽고 사내 결정(징계·고소·합의)을 내린다. 도구를 쓰지 않는다. 한컴·Acrobat·브라우저 뷰어.
- **오늘**: 영문 절 제목·`status=`, PDF 한글 글꼴 미포함·Letter 판형, 세로선 문자 표. 표시한 USB 연결·로그온 기록의 값이 본문에 없다(파일만 실린다).
- **더 낫다**: 한국 법률 문서 관례(표지·목차·쪽 번호·별지·증거 번호)의 A4 문서, 문장마다 출처·시각·시간대, 한계 절.

### 1.5 QA·검증 담당

- **목표**: "동작한다"는 주장을 실데이터로 확인하고 증거가 바뀌지 않았음을 매번 증명한다.
- **맥락**: Sonnet 워커 + 사람 1명. Playwright·CLI. 실데이터는 Git 밖.
- **오늘**: 정답을 아는 코퍼스가 없다. 대조 도구가 설치돼 있지 않다. 워크트리 67개가 포트와 프로세스를 다툰다. e2e가 사용자 브라우저에 토큰 탭을 연다.
- **더 낫다**: 코퍼스 6종과 매니페스트, 번호 붙은 시나리오 201개, 게이트 한 줄, 워크트리마다 고유 포트, 증거 스냅샷 자동 비교.

### 1.6 개발자(유지보수) — 대부분 에이전트다

- **목표**: 4시간짜리 과제를 워크트리 하나에서 끝내고 15분 안에 전체 게이트의 답을 받는다.
- **오늘**: CI 빨강. 로컬 게이트와 CI가 다른 답을 낸다. AGENTS.md가 쓰지 않는 명령을 가리킨다. 빌드 산출물이 Git에 있어 병렬 UI 과제가 충돌한다. e2e 단언의 53%가 한글 리터럴이다. 2,160줄짜리 파서 함수 하나.
- **더 낫다**: `gate.py` 한 줄, 초록 CI, 구조 래칫, testid 상수·문구 사전, 묶음 끝 코디네이터 빌드.

### 1.7 자동화·AI 에이전트(AX)

- **목표**: 문서 한 장을 읽고, 문자열을 파싱하지 않고, 사건 만들기 → 처리 → 질의 → 검토 → 보고서를 끝낸다. 중간에 끊겨 다시 불러도 같은 결과가 나오고, 증거 속 글자가 에이전트를 조종할 수 없다.
- **오늘**: `--json` 없는 명령 12개, 실행 오류가 전부 사용법 오류(종료 2 + 사용법 전문), 도움말 1.5초, 출력 209 KB, 멱등 키 없음, 사건 요약 엔드포인트 없음, OpenAPI 태그 0.
- **더 낫다**: `/brief` 한 번, `_envelope` 한 키·오류 코드 한 표·종료 코드 5종, 기동 0.5초·출력 32 KB, `commands --json`, 멱등 키와 대기, 읽기 전용 서버.

### 1.8 법원·상대방 감정인(산출물의 적대적 독자)

- **목표**: 보고서의 약점을 찾는다 — 증거가 바뀌지 않았나, 전부 봤나, 재현되나, 숫자가 맞나, 시각이 맞나, 누가 판단했나.
- **오늘 공격받을 곳**: 감정서의 해시 표 공란·추출 사본 해시·가짜 "인수 시각"·증명하지 않은 "읽기 전용" 단정, 도구 버전 미기재, 범위 미기재, 컨테이너/매체 해시 혼동, 캐시 해시, 덮어쓰는 감사, 작성자 `web-ui`, 시간대 없는 시각, A등급 규칙 참양성 0, 잡음 수치.
- **더 낫다**(우리에게): 공격할 곳이 문서에 이미 "한계"로 적혀 있고 나머지는 재현된다. 제품은 **사실 진술 여섯**(동일성·무결성·신뢰성·완전성과 정직성·귀속·최소 처리)을 기록으로 뒷받침한다.

## 2. 사용 시나리오

로펌에서 흔한 사건 여덟. 각 단계는 "오늘 막히는 곳(GAP)"과 "이상적 흐름(IS)"을 적는다. 화면 물결(WF·WG)의 Fable 리뷰는 이 시나리오를 그대로 걸어 본다.

### S-1 정보유출 내부조사(퇴사 예정자 PC)

1. 분석 담당이 E01 2개로 새 사건을 만든다. → 오늘: 입력 32개, 경로 오타로 고아 사건(GAP-076), 디스크 여유 점검 없음(GAP-183). 이상: 2단계·입력 5·여유 경고(IS-008·160).
2. 밤새 처리. 아침에 탭 제목이 "(!) 사건 · …"이다. 브리핑 첫 구역: 파티션 2/2 · 할당 100% · 삭제 레코드 목록 100%·내용 판정 · 처리 제한 2건. → 오늘: 삭제 43만 건이 목록에도 없는 것을 모른다(GAP-245). 이상: IS-004·126·132·152.
3. 변호사가 링크로 들어와(검토자 기본값) 60초에 파악. → 오늘: T1 실패. 이상: IS-001·018.
4. "반출 경로" → USB: 장치별 최초·최종 연결·연 파일 수. 그 문서 148건을 검토 묶음으로(스냅샷). → 오늘: USB가 3노드(GAP-088), 묶음 없음. 이상: IS-030·040.
5. 하루 보기로 퇴사 전날: 14:01 문서 수정 → 14:03 열람(이동식) → 14:05 USB 연결. 내려받은 파일의 출처(Zone.Identifier). → 오늘: 5조작·3화면(GAP-114), ADS 0건(GAP-247). 이상: IS-047·153.
6. 12건(파일 6 + USB·로그온 등 아티팩트 행 6) "보고서 포함" → 미리보기 → 점검 → A4 PDF. → 오늘: 미리보기 없음, 아티팩트 행의 값이 본문에 없다(GAP-298). 이상: IS-056·138.
7. 상대방이 "삭제 파일은?" → 삭제·복구: 전수 목록, 내용 상태(복구 가능·0으로 채워짐·덮였을 수 있음) 구분. → 오늘: 61%가 0 채움 덤프(GAP-041·245). 이상: IS-023·152.

### S-2 근로·노무(근무 시간·업무 외 사용 다툼)

1. 브리핑의 사용 기간·활동 시기로 근무 패턴 확인. → 위험: 폴더 증거면 사본 시각뿐(GAP-171), 이미지 증거도 파일 시각이 처리한 날(GAP-246). 이상: "산정 불가" 고지와 증거 시각(IS-050·151).
2. 계정·로그온: 로그온·잠금 해제 시각을 날짜별로. → 오늘: 로그온이 이벤트 로그 아래 묻힘(GAP-083), 시각 표기 3종(GAP-116). 이상: IS-049.
3. 웹 › 방문·검색어. 0건이면 사유. → 오늘: 사유 없음(GAP-038), 복구 모드가 브라우저 수집을 뺀다(GAP-279). 이상: IS-006·155.
4. 보고서에 표시 시간대와 시각 근거가 자동 기재(IS-059).

### S-3 횡령(재무 담당자)

1. 사건 키워드: 계좌·송금·이체·상대 회사명. → 오늘: 기본 키워드 전부 영문(GAP-107).
2. 검색 "계좌" → 문서 120건(한 파일 한 줄) → 묶음 → 한 건 보기로 키보드 검토, 읽은 항목은 굵기가 내려간다. → 오늘: 중복 행·12자 미리보기(GAP-103). 이상: IS-031·041·130.
3. 개체 패널: 계좌번호·카드번호 후보. → 오늘: "Failed to fetch"(GAP-051). 이상: IS-037.
4. 공동인증서 흔적(주체 정보 기본 가림)·한컴 최근 문서(승인 뒤, IS-159). 보고서에 가림 처리된 계좌 + "원문은 증거와 같다" 고지(IS-053).

### S-4 계약 분쟁(문서 작성·수정 시점)

1. 계약서 파일명 검색 → 뷰어 "정보": 생성·수정·최종 저장자, "관련 흔적" 탭. 경로는 증거 안 경로다. → 오늘: 결과 폴더 경로(GAP-335). 이상: IS-128.
2. 시각이 취득 사본 시각인지 증거 시각인지 표식으로 구분(IS-050). → 오늘: 이탤릭으로만(GAP-117).
3. 타임스탬프 조작 의심 → MFT·USN 전량(승인 뒤, IS-154). → 오늘: MFT 0.5%·USN 0행(GAP-262·263).
4. 본문의 구절을 끌어 인용 복사해 준비서면에 붙인다(IS-131). R7 때 붙인 인용도 계속 열린다(IS-015).

### S-5 가사(이혼 — 메신저·사진·위치)

1. 메신저: 카카오톡 메시지 0건 → "이 저장소는 읽을 수 없습니다" 사유 + 대화방 수·마지막 활동(메타, 승인 뒤). → 오늘: 사유 없음(GAP-158·281). 이상: IS-006·159.
2. 사진: 썸네일, 민감 사진 흐리게 기본, 깨진 이미지는 대체 글리프. → 오늘: 빈 사각형·콘솔 오류(GAP-097).
3. 위치: 좌표 행이 있으면 지도, 없으면 사유. → 오늘: 0행이 사람 표로 연결(GAP-081).
4. 의뢰인에게 나가는 보고서는 "법원 제출용" 프로파일(증거 안 상대 경로만, 가림)로(IS-128·136).

### S-6 형사 변호 지원(수사기관 분석에 대한 반박)

1. 첫 질문은 무결성. → 오늘: 컨테이너 해시를 비교해 거짓 불일치(GAP-007), 이미지에 기록된 취득 해시를 읽지 않는다(GAP-248). 이상: 컨테이너·취득·매체 해시 구분(IS-069). 매체 재계산은 **[승인 D34b]**, 그 전에는 "입력값 = 이미지에 기록된 취득 해시(매체 재계산 안 함)".
2. "피고인이 그 시각에 PC를 썼는가": 계정·로그온 + 하루 보기. 규칙 적중은 "자동 · 검증 전" 표시(IS-124).
3. 감정서: "감정 대상 증거" 표(세그먼트별 해시·기록된 취득 해시)와 "제출 항목" 표, 인수 기록 5칸(승인 뒤), 도구 버전·범위·한계. → 오늘: GAP-009·294~296. 이상: IS-139·147.
4. 상대방 감정인이 재현할 수 있게 처리 이력 부록, 줄 사슬이 있는 내보내기 감사, 보존된 보고서 판을 함께 낸다(IS-141·142).

### S-7 AI 도구 사용 조사 — 개발자 PC

1. "AI 사용" → 개요 네 칸: AI로 나간 것 / 계정 / AI가 한 일 / 남지 않은 것. → 오늘: 답이 세 화면(GAP-118), 실데이터 콘솔 미검증(GAP-048), E01에서 행이 나온 적 없음(GAP-316).
2. 세션 → 요약 카드(틀 고정, 생성 없음) → 대화 보기. 키·토큰은 `[가림]`. 큰 붙여넣기는 절단 표시 + 원문 해시 + 원본 줄로 이동(승인 뒤). → 오늘: 16 KB에서 잘리고 돌아갈 길 없음(GAP-317).

## 5. 디자인 시스템과 화면 설계

전문은 [부록 C](r8/r8-design-system.md)(C.0 개정 요약, C.9 추가 규격), 계약은 [부록 D](r8/r8-contracts.md).

- **원칙**(충돌하면 위가 이긴다): ① 화면은 틀린 사실을 말하지 않는다. 모르면 모른다고 쓴다 ② 첫 화면은 사건이다 ③ 읽는 화면은 읽기 좋게, 훑는 화면은 훑기 좋게 ④ 색은 네 가지 뜻에만, 항상 모양과 글자와 함께 ⑤ 숨긴 것은 숫자로 말하고 한 번에 편다 ⑥ 분석 담당의 손은 바꾸지 않는다 ⑦ 화면은 하나, 역할은 기본값만.
- **IA**: 레일 5개(사건·처리·살펴보기·검토·보고서), 주소 단어와 `Alt+1~5` 불변. 처리 중에만 진행 띠. ⚙에는 설정·환경 점검만. 신규는 하위 주소 6개와 `?share=1`.
- **역할 기본값**: 묻지 않고 추론, 상단 스위치. 바뀌는 것은 레일의 "처리"·전문가 항목 펼침·밀도·헥스/SQLite 탭뿐.
- **기준 화면**: 1280×720. 브리핑 구역 순서는 범위·무결성 → 대상 PC → 무엇이 나왔나 → 규칙이 표시한 것(자동 · 검증 전) → 검토.
- **핵심 화면 12**: 진입 / 사건 브리핑 / 살펴보기(목록 + 뷰어) / 검색 결과 / 하루 보기 / AI 개요 / 검토(묶음·한 건 보기) / 보고서(구성·종이·점검) / 새 사건·새 처리 / 처리(이력·요약·더 분석하기·산출물) / 사람·장치 / 설정 팝오버.
- **시각 언어**: 크롬 무채색. 색 4계열(처리 상태 / 포렌식 상태 / 규칙 등급 / 사람의 판단 = 보라). 빨강은 실패·불일치·A등급에만. 글자 7단 + 읽기 15/26, 이탤릭 금지. 토큰은 역할 이름.
- **컴포넌트**: 화면이 끌어낸다(브리핑 → 목록·뷰어 → 검토 → 보고서). 수렴은 마지막(WH).
- **계약**(부록 D): 주소·인용·단축키·저장 키·접근성 이름·랜드마크. testid는 상수 모듈. CLI는 `_envelope` 한 키. 증거에서 온 글의 자리.

## 9. 1:1 검증 절차

목표: 구현이 끝난 화면이 이상적 상태 173문장과 **하나씩** 같다는 것을 증거로 보인다. 다르면 예외 없이 다시 계획한다.

### 9.1 추적표

[부록 G](r8/r8-traceability.md): IS → GAP → 과제 → QA → 판정. 부록 A·B·E·F의 데이터에서 **스크립트로 생성**했다. 생성 시점 검사 결과는 전부 0이다 — GAP 없는 IS · 과제 없는 IS·GAP · QA 없는 IS · 닫는 과제 없는 QA · GAP/IS 없는 과제 · QA도 사유도 없는 과제 · 없는 ID 참조 · 폐기된 과제 의존 · 뒤 물결 의존 · 4시간 초과 · 6개 초과 묶음 · 묶음 안 파일 충돌(부록 G.4). 과제를 더하거나 고치면 같은 검사를 다시 돌려 묶음과 추적표를 새로 만든다(T-003이 생성기를 저장소 스크립트 `scripts/r8-trace-audit.py`로 옮긴다).

### 9.2 판정 규칙

| 판정 | 조건 |
|---|---|
| **일치** | 그 IS의 QA가 전부 실데이터에서 통과했고, 증거(스크린샷·JSON·파일 경로)가 추적표에 연결돼 있고, Sonnet 재실행과 Fable 확인이 끝남 |
| **불일치** | QA 하나라도 실패, 또는 통과했지만 Fable이 IS 문장과 다르다고 판단(QA가 문장을 덜 덮음) |
| **미검증** | 대상 데이터가 없거나 승인이 없어 실행 불가. 부록 E.5·E.7의 사유 목록에 있을 때만 허용하고 known-limitations·릴리스 노트에 적는다. 합성만 통과는 "미검증"이다 |

"거의 됐다", "다음에", "환경 문제"는 판정이 아니다. 수치 기준은 반올림하지 않는다.

### 9.3 서명

- 과제: 구현자(Opus)가 아닌 세션(Sonnet)이 수용 검사와 검증 명령을 처음부터 다시 실행한 로그 + 실데이터 증거.
- 물결: Fable이 (a) diff 전체 (b) 추적표의 해당 행 (c) 2절 시나리오를 걸어 본 기록 (d) 증거 스냅샷 diff (e) CI 실행 기록을 보고 S1·S2 0을 확인. 발견은 GAP-359 이후로 등록.
- 릴리스: 사업 소유자. 추적표 판정 열, 미검증 목록, 사람 테스트 결과, 엔지니어링 기준선과 릴리스 증거의 구분을 받는다.

### 9.4 불일치가 나오면(재계획 루프)

1. Fable이 불일치를 GAP으로 적는다(증거·IS·심각도).
2. 원인을 셋 중 하나로 가른다: 구현 결함 / 과제 누락(계획 결함) / IS 문장이 틀림(이상 정의 결함). 셋째는 사업 소유자 결정 없이는 IS를 고치지 않는다.
3. 4시간 이하 과제로 쪼개 다음 묶음에 넣는다(생성 스크립트가 파일 배타를 다시 검사한다). 같은 IS가 두 번 불일치하면 그 영역의 설계를 다시 검토한다.
4. 고친 뒤 그 IS의 QA **전부**와 회귀 묶음을 다시 돌린다(실패한 QA만 재실행 금지).
5. S1 불일치가 열려 있으면 다음 물결을 시작하지 않는다. S2는 물결 끝까지, S3는 WH까지 허용.

### 9.5 사람 테스트(D2)

WF 끝(T-346, T1 중심)과 WZ(T-128, T1~T5)에 분석 담당 3·변호사 2. 60초 뒤 6문항, 과제별 조작 수·시간, 막힌 곳 발화 기록(이름·소속은 적지 않는다). 사람을 못 구하면 "사용자 미검증"으로 표기하고 IS-001·034 관련은 "미검증"으로 남긴다.

- **묶음은 스크립트가 만든다**: 6개 이하·파일 배타·의존 선행. 손으로 고치지 않는다.
- **최소 충족선**: **WA~WC** = 틀린 것을 바로잡고 실데이터로 확인(의심 해소) · **WE** = 첫 화면이 사건 · **WG** = UI/UX 개편 완료 · **WH** = 정리 · **WP** = 승인 시.
