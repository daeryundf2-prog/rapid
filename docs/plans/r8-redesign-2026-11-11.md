## 3. 목표 경험

### 3.1 레이아웃 결정: A안(브리핑 우선) 셸 + B안(한 건 보기)을 검토의 모드로 + C안(시간·인물 축)은 "시간순"의 보기로

UX 감사 §8.6의 세 안 중 A를 셸로 고른다. 이유:

- T1(1분 파악)을 직접 푼다. 현재 실패한 유일한 과제다.
- 지금의 3단 구조(좌 내비·중앙 목록·우 뷰어)와 해시 라우트, `data-testid` 277곳, 접근성 이름을 그대로 쓸 수 있어 비용과 회귀 위험이 가장 낮다.

```
│ [로고] [사건 이름 ▾]   [ 검색: 문서·대화·파일…            ] [⌘K] [⚙ 전문가] │
├ 전역 내비(4) ───────────────────────────────────────────────────────────┤
│  사건      살펴보기      검토      보고서                                  │
└─────────────────────────────────────────────────────────────────────────┘
⚙ 메뉴: 전문가 모드 켜기 · 처리 이력(증거별) · 증거 관리 · 산출물 · 설정 · 도움말
상태바: 처리 상태 한 단어 · 표시 시간대 · 연결   (런 ID 없음)
```

- **사건**(홈): 사건 브리핑 한 화면. 현재 "접수"를 대체한다.
- **살펴보기**: 좌측 범주 내비(12개 이하) · 중앙 목록 · 우측 미리보기. 현재 "탐색"을 대체한다.
- **검토**: 검토 묶음·진행률·태그. R8-4에서 한 건 보기 모드 추가.
- **보고서**: 포함 항목 · 미리보기 · 의견 · 내보내기.
- **처리**는 전역 내비에서 빠져 ⚙ 아래 "처리 이력"으로 간다. 처리 중일 때만 상단에 진행 띠가 뜬다.
- 화면에서 "런"이라는 말은 쓰지 않는다. 사건 아래 "증거"와 "처리(n차)"로 부른다(결정 D11). CLI·API의 `run`은 그대로 두고 용어 대응표에 적는다.

### 3.3 살펴보기의 범주 내비(기본 12개 이하)

```
주요 발견            12        ← 특이사항 A·B (가로지르는 보기)
────────────
문서                 1,204
이메일               0  ⓘ     ← 0건이어도 남기고 사유
메신저               38
웹                   6  ⓘ
반출 경로            460       ← USB·클라우드·원격·공유·인쇄
프로그램 실행        331
삭제·은닉            54
계정·로그온          158
AI 사용              0  ⓘ
────────────
시간순                         ← 하루 보기(가로지르는 보기)
사람·장치                      ← 계정·장치·보관자 묶음(가로지르는 보기)
────────────
더 보기 ▸ (Tier 2 묶음 7개, 접힘)
전문가 항목 43.2만 건 숨김 ▸   ← 전문가 모드에서 기존 트리
```

- 항목은 "가로지르는 보기 3개 + 항상 보이는 카드 9개 = 12개"다. 사건 유형에 따라 조건부 카드(사진·영상, 위치, 통화·연락처)가 건수가 있을 때 "더 보기" 맨 위에서 본 목록으로 올라온다(그때는 0건·사유 없는 카드가 없으므로 총수는 12 안에서 프리셋이 정한다).
- 항목을 누르면 반드시 본문이 바뀐다(펼치기만 하고 본문이 그대로인 동작 금지). 카드에는 하위 탭(예: 웹 = 방문 · 검색어 · 다운로드 · 업로드 후보)이 목록 위에 붙는다.
- 0건 카드의 ⓘ는 사유 한 줄과 다음 행동을 보여 준다(4.3절).
- 뷰어를 열어도 내비는 접히지 않는다(아이콘 폭으로 줄어들 뿐, 한 번에 복귀).

### 3.5 상호작용 규칙

1. 누르면 본문이 바뀐다. 펼침 전용 클릭 없음.
2. 한 화면에 주 행동(Primary) 버튼 하나.
3. 쓸 수 없는 것은 숨긴다(메뉴·탭·팔레트). 예외는 "왜 못 쓰는지"가 다음 행동인 경우(0건 사유).
4. 시각 표기는 표시 시간대 하나(`YYYY-MM-DD HH:mm:ss` + 상태바의 시간대). ISO 원문·UTC 문구는 기본 뷰에서 0. 원문은 "기술 정보".
5. 숫자는 링크다. 링크가 여는 목록의 건수는 그 숫자와 같다(계약 테스트).
6. 쓰기 전 확인 대화상자와 경로 고지는 유지한다(현재의 장점).
7. 뷰어를 열어도 좌측 내비는 남는다. 목록 선택은 화면을 옮겨도 유지한다.
8. 점진적 공개 3단: 기본(정제 목록·6열·미리보기) → "자세히"(전체 필드·출처·관련 행) → 전문가 모드(전체 트리·헥스·SQLite·조건 전체·워크벤치·산출물). 전문가 모드는 사용자별로 기억한다.
9. 키보드: 검토 R(관련)·I(무관)·T(태그)·P(보고서 포함)·J/K(다음·이전), 보기 전환과 열 머리글은 roving tabindex.
10. 숨긴 것은 숫자로 말한다("전문가 항목 n건 숨김", "처리 제한 사항 n건").

### 3.7 한국어 용어 정책

1. 기본 뷰에는 일상어만 쓴다. 원어는 도움말과 "기술 정보"에 병기한다(예: "프로그램 실행 기록(Prefetch)"은 전문가 모드에서만 괄호를 보인다).
2. 한 개념 한 이름: 검토(리뷰·선별 금지), 분석관(검사관·검사자·분석자 금지 — R7 단계 6 용어 지도 승계), 처리(런 금지), 주요 발견(특이사항은 전문가 모드 용어로 남김), 보고서 포함, 범주(계열·도메인 금지), 전문가 항목.
3. 값도 번역한다. 내부 토큰(`[a-z]+[-_][a-z]+`)이 기본 뷰에 나오면 게이트 실패. 카탈로그 `value_labels`가 단일 출처다.
4. 서버 오류는 한국어 문장 + 기계용 코드 + 다음 행동(`{code, message, hint}`).
5. 프로필 기본 키워드는 한국어(사건 유형별, 결정 D4). 보고서 절 제목 영문 0.
6. `docs/console-glossary.md`가 단일 출처이고 용어 lint(`scripts/check-glossary-terms.py`, 신규)가 금지 표기를 CI에서 잡는다.
7. CLI·API 이름은 영어로 두되 "화면 용어 ↔ CLI/API 이름" 대응표를 에이전트 안내 문서에 싣는다.

## 4. 아티팩트 표시 모델

### 4.1 분류 하나로 통일(감사 두 건의 충돌 해소)

충돌: UX 감사는 "범주 10개", 아티팩트 검토는 "Tier 1 카드 11장", 대시보드는 12범주, 트리는 16도메인(최상위 21). 코드에는 분류 출처가 다섯 군데다(C4).

**결정**: 계열 카탈로그(`rapidtriage/core/triage_rules/catalog/*.yaml`)에 키 세 개를 넣고 이것만 읽는다.

```yaml
families:
- id: usb
  tier: 1            # 1 = 항상 첫 화면, 2 = 더 보기, 3 = 전문가
  card: exfil        # 아래 카드 id 중 하나
  section: usb       # 카드 안 하위 탭
```

- **카드 9개(항상)**: `documents` 문서 · `email` 이메일 · `chat` 메신저 · `web` 웹 · `exfil` 반출 경로 · `programs` 프로그램 실행 · `deleted` 삭제·은닉 · `accounts` 계정·로그온 · `ai` AI 사용.
- **조건부 카드 3개**(사건 유형 프리셋이나 건수로 승격): `media` 사진·영상 · `location` 위치 · `calls` 통화·연락처.
- **가로지르는 보기 3개**(행을 소유하지 않음, 카드가 아님): 주요 발견 · 시간순 · 사람·장치.
- 11장과의 차이: 아티팩트 검토의 "USB·외부 장치"와 "클라우드"를 `exfil` 한 카드의 하위 탭(USB · 클라우드 · 원격·공유 · 인쇄)으로 합쳤다. 두 카드가 같은 질문("어디로 내보냈나")에 답하고, 내비를 12개 이하로 지키기 위해서다. "타임라인"은 카드가 아니라 보기다. 웹메일·웹하드 업로드 후보는 `web`이 소유하고 `exfil`에는 링크 칩으로 건수만 보인다(행 중복 0 원칙).
- 10개와의 차이: UX 감사의 "문서·메일"을 둘로 나눴다(이메일은 0건 사유를 따로 말해야 한다). "프로그램·계정"도 둘로 나눴다(계정은 행위자 특정의 축이다).
- Tier 2 묶음 7개(더 보기): 사용 흔적 보조 · 브라우저 보조 · 시스템 맥락 · 이벤트 로그 · 검토 관리(예외·중복·개체·압축 목록) · 모바일 세부 · 침해 흔적(침해사고 프리셋이면 Tier 1로).
- Tier 3: `card: expert`. 전문가 모드에서 기존 16도메인 트리 그대로(노드 id·경로·북마크 유지).
- 폐기: `categories.ts`의 12범주 표, 대시보드의 별도 분류. `domains.ts`와 `core/artifact_domains.py`는 전문가 트리 전용으로 남기되 카탈로그에서 생성한다(손으로 맞추는 사본 금지, 생성 스크립트 + 동기화 테스트).
- 행 하나는 정확히 카드 하나에 속한다. 다른 카드에서 필요하면 링크 칩으로만 보인다. 그래서 "부모 건수 = 자식 고유 행 수"가 항상 성립한다.

### 4.2 계열에 속하지 않는 유형(행의 약 90%) 처리

1. 카탈로그에 `type_defaults.yaml`을 추가한다. 모든 `artifact_type`은 (계열의 tier·card) 또는 (type_defaults의 tier·card)로 반드시 풀린다. 규칙 순서: 계열 → 유형 기본값 → kind 기본값 → "분류 안 됨"(Tier 3).
2. IMG-B 유형 목록(`type_counts_imgb.json`의 유형 이름과 건수, 식별자 아님)으로 초기 분류한다. 대량 유형은 Tier 3: 레지스트리 키 트리 노드(43.1만), 삭제 셀·키·값 복구 후보(약 2.8만), 시그니처 불일치(2.3만), Prefetch 참조 경로(1.3만), 원시 이벤트(1.6만), ETL·EVTX 파일, 브라우저 캐시, 서비스 설정, 인벤토리·요약·오류 행.
3. Tier 1·2인데 열 정의가 없는 유형은 계열을 새로 만든다: 메모지, 사용자 프로필, 브라우저 프로필 계정·세션 탭·상위 사이트, 원격 제어 도구, 무선 프로필, 알림·활동 기록, 인쇄 스풀, Windows Search 행, 데스크톱 AI 앱.
4. 게이트: 카탈로그 검증이 `tier`·`card` 누락을 오류로 잡고, 수집기가 낼 수 있는 유형 목록(`core/artifact_taxonomy.py`의 등록부) 전부가 풀리는지 검사한다. 런타임에 모르는 유형이 나오면 Tier 3 "분류 안 됨"으로 세고 `/brief.limits`에 건수를 싣는다.
5. 수용 기준: IMG-B에서 기본 뷰에 보이는 행이 전체의 15% 이하, "분류 안 됨" 0, Tier 1·2 유형 중 kind 기본 열로 떨어지는 것 0.

### 4.3 Tier 1 카드와 0건 사유

카드는 ① 건수 ② 기간 ③ 주요 발견 수 ④ 대표 3건(하위 유형별 건수) ⑤ 0건이면 사유와 다음 행동을 보여 준다. 사유는 서버가 코드로 준다(`zero_reason.code`), 문장은 한국어 사전에서 만든다.

| 사유 코드 | 문장(예) | 다음 행동 |
|---|---|---|
| `not_collected_mode` | 이 처리는 복구 모드라 브라우저·실행 흔적을 수집하지 않았습니다 | 추가 수집 |
| `collector_failed` | 브라우저 수집이 오류로 중단됐습니다(부분 결과 n건) | 처리 제한 사항 보기 · 다시 수집 |
| `container_only` | 메일함 n개가 있지만 메시지를 읽지 못했습니다(PST 읽기 구성 요소 없음) | 설치 안내 |
| `encrypted_store` | 카카오톡 DB n개는 새 암호화 방식이라 열지 못했습니다 | 키 입력 절차 안내 |
| `scope_truncated` | 볼륨의 n%만 처리해 이 범주가 비어 있을 수 있습니다 | 나머지 처리 |
| `no_input` | 모바일 추출본이 증거에 없습니다 | 증거 추가 |
| `none_found` | 수집했지만 해당 기록이 없습니다 | — |

`none_found`는 해당 수집기가 완료 상태이고 대상 파일을 실제로 읽었을 때만 쓴다(침묵 실패 점검 결과와 연결). 그 밖에는 "없다"고 말하지 않는다.

### 4.4 카드별 기본 열(6개 이하)

| 카드 | 기본 열 | 보조(숨김) |
|---|---|---|
| 문서 | 시각 · 행위(열람·수정·생성·인쇄) · 문서 이름 · 폴더 꼬리 · 위치(로컬·이동식·네트워크·클라우드) · 계정 | 근거 유형, 크기, 해시, 작성자·최종 저장자 |
| 이메일 | 보낸 시각 · 보낸 사람 · 받는 사람 · 제목 · 첨부 수 · 방향 | 메일함, 스레드, 참조 |
| 메신저 | 시각 · 앱 · 대화방 · 발화자 · 본문 · 첨부 | 방향, 메시지 id |
| 웹 | 시각 · 종류(방문·검색·다운로드·업로드) · 제목/검색어 · 호스트 · 분류 · 브라우저 | 프로필, 전체 URL, 전환 유형 |
| 반출 경로 | 시각(최종) · 경로 종류(USB·클라우드·원격·공유·인쇄) · 이름(장치·서비스) · 행위·대상 · 계정 · 건수(연 파일·올린 파일) | 시리얼, 최초 연결, 드라이브 문자, 볼륨 시리얼 |
| 프로그램 실행 | 프로그램 · 최종 실행 · 실행 횟수 · 최초 실행 · 계정 · 근거 수준(실행/존재) | 경로, 해시, 근거 유형별 시각 |
| 삭제·은닉 | 삭제 시각 · 이름 · 원래 경로 꼬리 · 크기 · 근거(휴지통·MFT·USN·카빙) · 복구 가능 | 레코드 번호, 시퀀스 |
| 계정·로그온 | 계정 · 종류(로컬·MS·도메인) · 최초 로그온 · 최종 로그온 · 로그온 횟수 · 연결 계정 수 | SID, 프로필 경로 |
| AI 사용 | 시각 · 도구 · 계정 · 프로젝트 폴더 · 요청 요약 · 접촉 파일 수 | 세션 id, 모델, 토큰 수 |
| 주요 발견 | 등급 · 발견(한 줄) · 시각 · 범주 · 근거 행 수 · 검토 상태 | 규칙 id@버전 |

카탈로그에 `card_columns:`(카드 단위 기본 열)를 추가해 계열별 `core_columns`보다 우선한다. 원시 필드(레코드 번호·오프셋·키 경로·해시·파서)는 "기술 정보"로 간다. 그리드에서 값이 전 행 같은 열("일치" 등)은 자동으로 숨긴다.

### 4.5 질문형 진입점(홈 "질문으로 시작")

저장된 보기(카드 묶음 + 필터 + 열)이고 주소로 공유된다. 해당 행이 0이면 사유를 보인다.

| 질문 | 여는 묶음 |
|---|---|
| 누가 무엇을 언제 반출했나 | 반출 경로 전부 + 웹 업로드 후보 + 압축 파일 생성, 시각순 |
| 어떤 문서를 열람·수정했나 | 문서 › 열람·수정 이력(문서 이름으로 묶음) |
| 누구와 연락했나 | 이메일·메신저·문자의 상대별 건수와 기간 |
| 무엇을 지웠나 | 삭제·은닉 + 브라우저 기록 삭제 흔적 + AI 보존 정리 |
| 그 시각에 누가 PC를 썼나 | 계정·로그온 + 계정별 활동 첫·끝 시각 |
| 무엇을 검색하고 찾아봤나 | 웹 › 검색어·방문 + 지도 URL + AI 질의 |
| AI에 무엇을 넣었나 | AI 사용 개요 |
| 처리하지 못한 것은 무엇인가 | 처리 제한 사항 + 예외 항목 + 복호 불가 저장소 |

사건 유형 프리셋(정보유출 / 내부조사·횡령 / 근로·노무 / 계약 분쟁 / 이혼·가사 / 형사)은 카드 순서·조건부 카드·기본 질문·기본 키워드만 바꾼다. 수집 범위는 바꾸지 않는다.

### 4.6 사람·계정·장치·보관자 묶음("사람·장치" 보기)

- **계정**: SAM 계정(SID)을 뿌리로, 같은 프로필 폴더 아래의 브라우저 프로필 계정·Office 연결 계정·클라우드 동기화 계정·메일 클라이언트 계정·메신저 사용자 ID·AI 계정을 붙인다. "추정 연결"임을 표시한다. 시스템·서비스·기본 계정은 기본 숨김(현재 사람 식별자 등장의 89%가 이벤트 로그 계정).
- **사람**: 분석관이 여러 계정·메일·전화·메신저 ID를 한 사람으로 묶는 수동 병합(별칭)을 케이스 DB에 둔다 **[승인 필요: 케이스 DB 스키마 추가]**. 자동 제안은 같은 메일 주소·같은 표시 이름까지만.
- **장치**: USB 시리얼·볼륨 시리얼을 키로 레지스트리·setupapi·마운트 장치·LNK·ShellBags를 장치 한 줄로 합친다(파생 표, 수집기 불변). 장치 한 줄 = 최초·최종 연결, 드라이브 문자, 볼륨 시리얼, 그 장치에서 연 파일 수.
- **보관자**: 증거 → 사람 귀속(R7 단계 5 갈래 D의 보관자). 모든 그리드에 보관자 필터 **[승인 필요: 스키마]**.
- 사람·장치를 누르면 "이 사람(장치)의 카드 9개"가 같은 컴포넌트로 다시 그려진다(필터만 다름).

### 4.7 기본에서 숨기는 것

0건 노드와 "결과 없는 계열 n개" 문구 / 처리 › 예외 항목, 해시 집합(목록 미설정), 인벤토리, 스캔 제외, NTFS 레코드·볼륨 정보, 수집 상태 노드 / 그리드의 파서·계열·유형·중복 열과 값이 전부 같은 열 / 뷰어의 쓸 수 없는 탭, 메타의 출처·파서·해석 범위 절 / 행 메뉴·팔레트의 쓸 수 없는 항목 / 새 처리의 처리 그룹 26개 / 상태바 런 ID / 검색 푸터의 색인 버전 / 통합 보기에서 카카오톡 공유 사진(첨부 표)·카카오톡 원본 후보(자격 증명 표)·Prefetch 참조와 파일 목록(경로 표) / 주요 발견에서 미디어 C등급 규칙(유사 사진·EXIF 없음·스크린샷).

숨겨도 검색·시간순·사람·장치에서는 Tier와 무관하게 찾을 수 있고(검색 결과에 "전문가 항목 포함" 토글), 전문가 모드 한 번으로 전부 보인다.

## 7. AX(에이전트·자동화 경험)

### 7.1 CLI

- **구조**: 최상위 12개(`case · run · search · brief · timeline · report · export · web · doctor · sample · evidence · config`) + `dev …`(벤치마크·재구조화 상태 등)·`qa …`(검증·준비도 약 35개). 구 이름은 1릴리스 동안 별칭으로 동작하고 stderr에 새 이름을 알린다(결정 D16). `rapidtriage --help`는 12개와 "권장 순서" 5줄만 보인다.
- **JSON**: 모든 명령에 `--json`. 봉투 하나: `{"command", "status", "data", "warnings": [], "errors": [{"code", "message", "hint"}]}`. `search --json`은 표준 출력으로(R8-0). 인자 오류는 사용법 3 KB 대신 `errors` 한 건과 종료 코드 2.
- **한국어 도움말**: `--lang ko` 또는 `RAPIDTRIAGE_LANG=ko`. 기본은 영어 유지(에이전트 호환). 모든 명령에 예시 1개 이상.
- **자동화 기본값**: `web --no-browser` 플래그와 도움말. 표준 출력이 터미널이 아니거나 `CI`가 설정돼 있으면 브라우저를 열지 않는다. 로컬에서도 `RAPIDTRIAGE_TOKEN`을 읽는다. 토큰은 `--json`일 때 봉투 안에만 싣는다.
- **안전**: 쓰는 명령 전부에 `--dry-run`. 출력 기본 위치는 증거 폴더 밖.
- **기동**: 지연 임포트로 1.0 s 이하(`doctor --json` 기준).
- **종료 코드 표**: 0 성공 · 1 실행 실패 · 2 사용법 · 3 부분 성공(제한 사항 있음) · 4 대상 없음.

### 7.2 API

- 태그 10개(사건 · 처리 · 브리핑 · 범주·목록 · 검색 · 검토 · 보고서 · 파생·연결 · 메타 · 전문가)를 165연산 전부에, 설명·200 응답 스키마 100%. 스냅샷 게이트가 누락을 잡는다.
- 오류 모델 하나: `{"code": "RUN_NOT_FOUND", "message": "처리를 찾을 수 없습니다", "hint": "GET /api/runs 로 목록 확인", "detail": …}`. 영문 "Not Found"·pydantic 배열·인증 오류도 같은 틀. 오류 코드표 `docs/api-error-codes.md`.
- **`GET /api/runs/{id}/brief`**(화면 홈과 1:1): `case`(이름·유형 프리셋) · `evidence`(개수·해시 검증·범위 %) · `machine`(OS·시간대·사용 기간) · `accounts`(계정 수·주 사용 계정 수·로그온 횟수) · `activity`(일별 건수, 가장 바쁜 날) · `findings`(상위 5: 등급·한 줄·시각·링크) · `cards`(9+조건부: 건수·기간·대표 3·`zero_reason`·링크) · `keywords`(적중 수) · `review`(진행률) · `limits`(제한 사항 코드·문장·건수) · `hidden`(Tier 3 건수). 식별자가 필요한 값(계정 이름 등)은 `?redact=1`이면 가린다. 크기 30 KB 이하, 200 ms 이하.
- `GET /api/commands`(팔레트 명령 목록과 활성 여부), `GET /api/runs/{id}/rows`(화면과 같은 필터·열).
- 읽기 전용 모드: `web --read-only`가 비-GET을 허용 목록 외 403으로(현재 감사·리뷰가 라우터에서 손으로 막던 것을 제품 기능으로).

### 7.3 에이전트 진입점

- `docs/agent-guide.md` 한 장: 읽기 전용 보장, 권장 순서(`doctor` → `run` → `brief` → `search` → `report`), JSON 봉투, 오류 코드, 딥링크 규칙, 화면 용어 ↔ CLI/API 이름 대응표.
- 콘솔: 잘린 셀은 `title`이 아니라 접근성 이름에 전체 값. 뷰어를 열어도 내비 유지(자동화가 멈추던 원인).
- MCP 서버(읽기 전용 도구 6개: brief · search · list · get-row · timeline · findings)는 기본 범위 밖, 결정 D12.

### 8.3 원본 보기 비밀값 가림과 증거 충실성

- 원칙: **증거와 저장된 행은 바꾸지 않는다. 가리는 것은 화면 표시와 기본 보고서뿐이다.**
- 원본·검색 스니펫·미리보기·카드에서 자격 증명·토큰 패턴(기존 `redact_secret_text` 재사용)을 기본 가림. "가림 해제"는 확인 대화상자 뒤 그 항목만, 케이스 감사 기록에 남긴다(누가·언제·어느 행).
- 내보내기: 변호사용 보고서는 가림 기본, 증거 제출용 내보내기(원본 파일·해시 목록)는 불변이며 그 사실을 대화상자에 적는다.
- 게이트: 합성 픽스처의 가짜 비밀값이 기본 뷰 DOM·API 목록 응답·보고서에 0건.
- 결정 D5(법무 확인)가 필요하고, 기본값은 위와 같다.

### 8.4 의존성·보안

- 잠금 파일(`requirements.lock` 또는 동등물)을 만들고 pip_audit를 그 기준으로 돈다. starlette 권고 10건은 FastAPI·Starlette 상향으로 해소하고, 못 올리는 것은 사유를 `docs/`에 적는다. 프런트는 `npm audit`를 같은 게이트에.
- `web`이 표준 출력에 토큰을 찍는 동작은 터미널일 때만, 자동 열린 탭의 토큰 조각은 유지(주소창에서 제거되는 현재 동작).
- 읽기 전용 서버 모드(7.2), 폴더 증거의 출력 기본 위치(5.1).
- 로그·오류 본문에 경로 전체·개체 원값이 실리지 않는지 정규식 스캔을 게이트에.

### 8.5 테스트·CI 비용

- `scripts/run-tests-parallel.py`(신규): 모듈 병렬 실행을 표준으로. CI 워크플로의 단일 `unittest discover`를 이것으로 바꾼다(AGENTS.md 명령 목록 갱신은 결정 D17).

- 느린 모듈 분석: 반복 픽스처 생성·실제 처리 실행을 모듈 단위 공유 픽스처로. 목표 전체 31분 → 15분.
