# R8 부록 C — 디자인 시스템과 화면 설계

마스터 5절. v1(`r8-redesign-2026-11-11.md` 3절)의 골격 결정(브리핑 우선 셸 + 검토의 한 건 보기 + 시간순 하루 보기)을 유지하고, 시각 감사(visual-audit)의 시각 언어를 채택하되 아래에서 충돌을 정리했다. 계약(주소·인용·testid·접근성 이름)은 부록 D.

## C.1 설계 원칙 (우선순위 순)

1. **틀리게 읽히지 않는다.** 건수는 잘리지 않고, 정의가 다른 수는 이름이 다르며, 0건은 사유를 말한다. (IS-005·014·029)
2. **사건 언어 먼저, 엔진 언어는 접어서.** 원시 키·파서명·처리 ID는 "기술 정보" 안에만. (IS-002·021)
3. **색은 판단에만.** 크롬은 무채색. 색이 보이면 처리 상태·포렌식 상태·등급·검토 판단 중 하나다. (IS-105)
4. **화면당 주 버튼 하나, 누르면 본문이 바뀐다.** (IS-013·109)
5. **숨긴 것은 숫자로 말한다.** 전문가 항목·필터·처리 제한. (IS-035·072)
6. **쓰기 전에 말한다.** "누르기 전에는 아무것도 쓰지 않습니다 / 원본 증거는 바꾸지 않습니다"는 유지. (IS-067)
7. **검사관의 손을 바꾸지 않는다.** 기존 단축키·딥링크·전문가 트리 유지. (IS-015·039)

〔2차〕 내비 맨 위("먼저 확인할 것" 위)에 **"질문으로 찾기 ▾"** 메뉴를 둔다(T-136, 결정 D41). 8문항 — 무엇을 가지고 나갔나 / 무엇을 지웠나 / 누구와 연락했나 / 어떤 문서를 열었나 / 어떤 프로그램을 썼나 / 언제 PC를 썼나 / 어디에 접속했나 / AI 도구를 썼나 — 각각이 조건이 걸린 목록 주소를 연다(v1 4.5 승계). 브리핑 본문에는 넣지 않는다(스크롤 0 유지). 항목 수 12의 계산에서 이 메뉴는 1개로 센다.

- 묶음 머리 12px/600, 항목 13px/400(부모가 자식보다 약한 현재 위계 역전 해소). 건수는 우측 정렬 고정 폭(`min-width: 7ch`, `flex:none`), 스크롤바 거터 예약 뒤에도 잘리지 않는다. 1만 이상은 `1.2만`으로 **명시적으로** 줄이고 정확한 수는 접근성 이름·툴팁에 둔다.
- 분석 담당 모드에서는 이 아래에 기존 트리(노드 id·순서 유지)가 그대로 온다. 빈 계열 토글 문구는 "자료 없는 범주 보기 ☐"(상태가 아니라 동작) 하나로.
- 분류 출처는 카탈로그 `tier`/`card`/`section`(IS-019). 카드 정의·0건 사유·카드별 6열은 v1 4.1~4.4를 그대로 승계한다(변경: 카드 이름 "삭제·은닉" → "삭제·복구"; "확장자 위장" 하위 탭은 GAP-040 정리 뒤 사용자 폴더의 문서·압축·이미지 서명 불일치만).

## C.3 화면 설계(와이어·구성 요소·상태)

모든 화면 공통 상태 5종: **로딩**(골격 1종, 300 ms 미만이면 표시 안 함) / **빈 상태**(사유+행동) / **오류**(무슨 일·영향·할 일 + 접힌 기술 정보) / **부분**(상단 호박 띠 "일부만 표시: 사유") / **숨김 고지**(목록 위 한 줄 "n건 숨김 — 사유별 · 모두 보기").

- 메뉴: 행 메뉴 = 뷰어 `…` 메뉴 = 8개(열기·관련·제외·태그·보고서 포함·전후 시각·같은 파일·더 보기). 포털 렌더 + 뷰포트 충돌 보정.

## C.8 이행 전략(회귀 없이 바꾸는 순서)

1. **계약 먼저**(부록 D): testid·접근성 이름·주소·인용·저장 키 표를 저장소에 넣고 계약 테스트로 고정. 그 뒤에 화면을 바꾼다.
2. **깨진 것부터**: 체크박스·메뉴 잘림·건수 잘림·글자 겹침·트리 공백·"알 수 없음초"·빈 상태 거짓말(물결 1). 구조 변경 전에 독립 수정.
3. **토큰·공용 컴포넌트를 추가 방식으로**: 새 토큰은 `--r8-*` 별칭으로 넣고 기존 토큰을 그 별칭에 연결 → 화면을 하나씩 새 컴포넌트로 옮김 → 옛 클래스 삭제는 마지막 물결. 한 PR에서 옛 것과 새 것을 동시에 지우지 않는다.
4. **새 셸은 감싸기**: 전역 내비 4개·역할 모드를 넣되 분석 담당 모드는 기존 화면 그대로. 기존 e2e 13스펙은 분석 담당 모드에서 계속 돈다.
5. **주소**: 새 주소는 추가, 옛 주소는 `canonicalizeHash`가 영구 변환(삭제 없음). 쿼리 키 30여 개는 그대로.
6. **저장 키**: `rapidtriage.v3.*`로 이관하는 1회 마이그레이션 + 옛 키 삭제, 런별 누적 키는 LRU 20.
7. **문구**: 용어 lint를 경고 → 오류로 2단계 승격. 테스트가 고정한 문구(MetaView 40·CaseDashboard 30 등)는 계약표의 접근성 이름만 남기고 나머지는 testid로 바꾼 뒤 변경.
8. **검증**: 물결마다 분석 담당 모드 회귀(기존 e2e) + 검토자 모드 과제 e2e + 실데이터 QA(부록 E).
