# R8 부록 A — 이상적 상태 (IS-001 ~ IS-125)

마스터: `docs/plans/r8-master-2026-11-11.md` 3절. 각 문장은 시험할 수 있어야 한다. "왜"는 그 문장이 없을 때 어떤 사용자가 무엇을 잃는지다. 수치의 기준 데이터는 따로 적지 않으면 IMG-B(100% 재처리본)다. **[승인]** = AGENTS.md 계약상 엔진·파서·스키마 변경이라 소유자 승인 뒤에만 착수.

사용자 약칭: 검(검사관/분석 담당) · 변(변호사 검토자) · 파(사건 책임자·파트너) · 의(의뢰인 측 수령자) · QA · 개(개발자) · AX(자동화·에이전트) · 상(법원·상대방 감정인).

## A. 첫 실행·사건 브리핑

| ID | 이상적 상태 | 왜 | 사용자 |
|---|---|---|---|
| IS-001 | 사건을 열면 첫 화면이 "사건 브리핑"이고 1440×900에서 스크롤 없이 6문항(주 사용 계정, 사용 기간, 주요 프로그램 3, 주요 발견 상위 5, AI 사용 여부, 다음 할 일)의 답이 DOM에 있다 | 변호사는 60초 안에 사건을 파악하지 못하면 도구를 닫고 검사관에게 전화한다(T1 실패가 현재 유일한 실패 과제) | 변·파 |
| IS-002 | 화면 제목은 사건명·사건 번호다. 증거 파일명·폴더명·런 ID는 "기술 정보" 안에만 있다 | 증거 파일명은 사건을 식별하지 못하고, 같은 이름의 처리 2건이 시각으로만 구분된다 | 변·파 |
| IS-003 | 증거 카드 첫 줄에 무결성 상태(검증됨·계산됨·미계산·불일치)가 방패+글자+색으로 있고, 불일치는 접을 수 없는 상단 경고다 | 법정에서 가장 먼저 묻는 사실이 가장 작게 표시되면 안 된다 | 검·상 |
| IS-004 | 처리 범위(볼륨의 n%, 미처리 파일 수)와 처리 제한 사항 건수가 브리핑 첫 화면에 항상 있다(0건이면 줄이 없다) | 31%만 처리한 결과를 100%로 믿고 "없다"고 보고하면 방어할 수 없다 | 전원 |
| IS-005 | 브리핑·내비의 모든 숫자는 링크이고, 링크가 여는 목록의 총건수가 그 숫자와 같다(자동 계약 테스트) | 숫자가 서로 다르면 어느 쪽도 인용할 수 없다 | 검·변·AX |
| IS-006 | 0건 카드는 사유 코드(`not_collected_mode`·`collector_failed`·`container_only`·`encrypted_store`·`scope_truncated`·`no_input`·`not_run`·`none_found`)와 역할에 맞는 다음 행동을 보인다. `none_found`는 수집기 완료+대상 파일을 실제로 읽었을 때만 쓴다 | "0건"이 "없음"인지 "안 봄"인지 모르면 부재 주장을 할 수 없다 | 변·상 |
| IS-007 | 첫 화면(사건 없음)은 "사건 열기 / 새 사건" 두 동작과 최근 사건 목록, 준비물 안내(증거 경로·사건 번호)다. 빠른 처리·샘플은 보조 메뉴다 | 비전문가에게 네 버튼이 같은 무게면 잘못된 길로 들어간다 | 변·검 |
| IS-008 | 새 사건·새 처리의 기본 입력은 5개 이하이고, 경로는 폴더 선택기로 고르며, 잘못된 경로·증거 안 출력은 사건이 만들어지기 전에 그 필드 옆 한국어 문장으로 막힌다(고아 사건 0) | 입력 32개와 바닥 12px 오류로는 변호사가 처리를 시작할 수 없다 | 검·변 |
| IS-009 | 처리 중에는 상단 진행 띠가 일상어로 현재 단계·n/m·경과를 보이고, 끝난 범주는 처리 중에도 열 수 있다. 폴링이 409를 반복하지 않는다 | 143분 동안 빈 화면이면 실패로 오해한다 | 검·변 |
| IS-010 | 증거가 여러 개면 증거 선택기와 "전체" 비교 표가 있고, 사건에 연결되지 않은 처리 결과는 머리줄에 "사건 정보 없음 — 사건에 연결"을 보인다 | 실제 사건은 PC·노트북·USB가 함께 온다 | 검·파 |

|---|---|---|---|

| IS-015 | R7까지의 모든 해시 주소·쿼리 키·인용 문자열이 새 화면에서 같은 대상으로 열린다(넘김 표 e2e) | 이미 보고서·메모에 붙여 둔 링크가 깨지면 근거 추적이 끊긴다 | 검·AX |
| IS-016 | 뷰어를 열어도 내비는 아이콘 폭으로 남고, 화면을 옮겨도 목록 선택·스크롤 위치가 유지된다 | 자동 접힘은 사람도 자동화도 길을 잃게 한다 | 검·AX |
| IS-017 | 모든 화면에 제목(h1) 하나, 한 줄 설명, 건수 표기 한 번이 있다 | 지금은 탐색에 제목이 없고 같은 건수를 세 번 읽는다 | 변 |

## C. 아티팩트 표시

| ID | 이상적 상태 | 왜 | 사용자 |
|---|---|---|---|
| IS-019 | 분류 출처는 카탈로그 하나(`tier`·`card`·`section`·`card_columns`)이고 모든 유형이 분류된다("분류 안 됨" 0, 다른 분류표 0) | 분류가 다섯 군데면 화면마다 다른 숫자가 나온다 | 개·검 |
| IS-020 | 범주별 기본 열 6개 이하, 시각 열 잘림 0, 잘린 셀 10% 이하(1440, 뷰어 열림), 내용이 같은 열 0 | 29~37%가 잘린 표는 읽을 수 없다 | 변·검 |
| IS-021 | 기본 뷰에 내부 토큰·영문 키·ISO 원문이 0개다(카탈로그 `value_labels` 단일 출처, e2e 게이트가 CI에서 항상 실행) | `zero-filled`·`failed_isolated`는 변호사에게 뜻이 없다 | 변·의 |
| IS-022 | "확장자 위장"에는 삭제 복구본·0 채움·고엔트로피 손상 파일이 섞이지 않는다. 그런 파일은 "내용 복구 불가"로 따로 센다 | 22,954건 중 대부분이 잡음이면 진짜 위장 파일을 못 찾고, 보고서 수치가 틀린다 | 검·상 |
| IS-023 | 삭제 복구 파일은 목록·뷰어에서 "복구본" 표식과 내용 상태(내용 있음·일부·내용 복구 불가)를 보이고, 기본 정렬에서 맨 위에 오지 않으며 폴더 트리에서 가상 위치로 표시된다 | NUL로 찬 뷰어는 도구 고장처럼 보이고, 복구본을 실제 폴더로 오해한다 | 검·상 |
| IS-024 | 뷰어 탭은 그 항목에서 쓸 수 있는 것만 보인다. 서버가 본문을 보류(`withheld`)하면 사유(자격 증명 파일 등)와 대안을 탭 자리에 문장으로 보인다 | 9탭 중 5개 비활성, 이유 없는 비활성은 막다른 길이다 | 변·검 |
| IS-025 | 메타 첫 화면 12필드 이하 + 접힌 "기술 정보", 출처 구역(원본 위치·시각 현지+UTC·해석 범위)은 뷰어 하단에 고정 | 90필드에서 법정이 묻는 세 가지를 찾을 수 없다 | 변·상 |
| IS-026 | 행 메뉴와 뷰어 ⋯ 메뉴는 같은 목록 8개 이하 + "더 보기"이고, 쓸 수 없는 항목은 나오지 않는다 | 24항목 중 9개 비활성은 쓸 수 있는 동작을 가린다 | 변 |
| IS-027 | 보기 전환은 `보기: 표 ▾` 글자 메뉴이고 가능한 보기만 나온다. 미리보기를 못 만드는 파일은 형식 글리프와 "미리보기 없음"을 보인다(415 콘솔 오류 0) | 빈 사각형 34칸은 고장으로 보인다 | 변 |
| IS-028 | 모든 필터·정렬은 전체 결과에 적용된다. 서버가 지원하지 않는 조합은 선택할 수 없거나 "전체에 적용되지 않음"이 결과 위에 크게 표시된다(조용한 부분 필터 0) | "docx 1건"이 불러온 2,250행 기준이면 누락을 모른다 | 검·상 |
| IS-029 | 목록은 총건수를 항상 보인다. 확정 전에는 "n건 이상", 예산으로 중단되면 "일부만 검색됨 — n행 확인"이다. 아무것도 세지 않으면서 "세는 중"이라고 하지 않는다 | 미확정 건수는 인용할 수 없다 | 검·상 |
| IS-030 | 사람·장치 보기: 계정(SID 뿌리)·장치(시리얼 키)가 한 줄로 묶이고 시스템 계정은 기본 숨김(숨긴 수 표시, 대화형 로그온이 있는 내장 계정은 보임) | 사람 식별자의 89%가 이벤트 로그 계정이라 사람을 찾을 수 없다 | 변·검 |

| IS-038 | 사건 키워드·키워드 팩의 적중 수가 브리핑에 있고 누르면 그 결과가 열린다 | 키워드 팩이 실제로 적용됐는지 확인된 적이 없다 | 변 |
