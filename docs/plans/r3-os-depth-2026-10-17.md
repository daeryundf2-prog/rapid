# R3 — 운영체제 심화·안티 포렌식·파일시스템 라운드 (2026-10-17)

근거: `docs/plans/axiom-parity-roadmap-2026-10-17.md` §2 R3, `docs/research/axiom-parity-matrix-2026-10-17.md` §4 갭 7·8·9·10·11·12. 목표: 운영체제 그룹 "있음" 32/49 → ≥45/49, 침해사고·내부자 조사에서 실행·삭제·타임스톰핑·인멸 흔적이 행과 지표로 나온다.

## 1. 최종 사용자가 보는 문제
- 어느 네트워크·공유·매핑 드라이브에 접속했는지(NetworkList·MountPoints2·Map Network Drive MRU·WLAN)가 레지스트리 키 목록에 묻혀 있다.
- Prefetch는 Win10 압축(MAM)을 풀지 못해 실행 횟수·8회 실행 시각·볼륨 테이블이 비어 `execution.runcount_spike` 규칙이 발화하지 않는다. PCA·FeatureUsage·Application Install States가 없다.
- VeraCrypt·CCleaner·Eraser·sdelete·BitLocker 복구 키 같은 인멸·암호화 도구 흔적을 한 곳에서 못 본다.
- NTFS 타임스탬프 불일치가 지표로만 있고 SI/FN 8열 표·노드가 없다. 이벤트 로그가 채널별 노드로 안 나뉜다. 카빙은 jpeg/png/pdf/zip/sqlite/gif/7z/rar뿐이고 결과가 계열 노드에 통합되지 않는다.

## 2. 이상 상태
- 레지스트리 도메인: 네트워크 프로필·공유/매핑 드라이브·WLAN 이력·Office 최근 파일·Known DLLs·기본 브라우저·PCA·FeatureUsage·설치 상태 노드가 각각 열 구성된 행으로 보인다.
- 실행 흔적: Prefetch 행에 실행 횟수·마지막 실행 8개·볼륨(이름·생성 시각·VSN)·참조 파일 수가 채워지고 `execution.runcount_spike`가 실데이터에서 발화한다.
- 안티 포렌식 도메인: `antiforensics.tool_present`(출처 명시 목록) 지표와 BitLocker 복구 키 파일 행.
- 파일시스템 › 타임스탬프 불일치 노드(SI/FN 8열 + 사유), $LogFile 트랜잭션 후보 노드.
- 이벤트 로그 › 채널별 서브노드(보안·시스템·응용·PowerShell·방화벽·작업 스케줄러·서비스·스토리지·사용자 PNP·Office Alerts·Defender).
- 복구/카빙: 오디오(wav/mp3/m4a)·Office(docx/xlsx/pptx=zip 서명+내용 검증)·HWP·EML·PE 시그니처 추가, 결과가 `recovery_method=carved` 행으로 해당 계열 노드에 함께 보인다.

## 3. 설계 — 3갈래
공통 규칙은 R2 §3과 같다(표준 라이브러리·바운디드·격리·한국어·카탈로그·트리 추가만·known-limitations).

### 3.1 O1 — 레지스트리 분류 확장 + 안티 포렌식 (`artifacts/windows/registry.py`, 새 `artifacts/windows/antiforensics.py`)
- 분류 항목 추가(하이브·내보내기 양쪽): `NetworkList\Profiles|Signatures\{Managed,Unmanaged}`(프로필명·설명·첫/마지막 연결·게이트웨이 MAC·DNS 접미사·카테고리) → `registry-network-profile`; `MountPoints2`·`Map Network Drive MRU`·`Network\<drive>` → `registry-network-share`; WLAN(`WlanSvc\Interfaces\...\Profiles`·`Wlansvc` 이벤트 보강) → `registry-wlan-profile`; Office `File MRU`/`Place MRU`(버전별 키, `[F00000000][T01D...]` 시각 파싱) → `registry-office-mru`; `KnownDLLs` → `registry-known-dll`; 기본 브라우저(`UrlAssociations\http\UserChoice`) → `registry-default-browser`; PCA(`Compatibility Assistant\Store`, `PcaAppLaunch.dic`·`PcaGeneralDb*.txt`) → `execution-pca`; `FeatureUsage\{AppSwitched,ShowJumpView,AppLaunch}` → `execution-feature-usage`; `Application Install States`(`Uninstall`·`App Paths`·MSI `Products`) → `registry-install-state`.
- 안티 포렌식: 설치 프로그램·Prefetch·Amcache·서비스·파일 이름에 대한 시그니처 목록(`catalog/antiforensics.yaml` 또는 규칙 params: VeraCrypt·TrueCrypt·BitLocker To Go·CCleaner·BleachBit·Eraser·sdelete·cipher /w·Privazer·Wise Disk Cleaner·timestomp·SetMACE·DBAN·KillDisk, 출처 명시) → 규칙 `antiforensics.tool_present`(B)·`antiforensics.wiper_run_after_incident`(A, 사고 기간 params); BitLocker 복구 키 파일(`BitLocker Recovery Key *.txt`·`.BEK`) 파서 → `bitlocker-recovery-key-file`(키 값은 저장하지 않고 가린 값·식별자·해시만).

### 3.2 O2 — Prefetch 완전 디코딩 + 이벤트 로그 채널 노드 (`artifacts/windows/prefetch.py`, `eventlog.py`, `domains.ts`)
- MAM(XPRESS Huffman, `MAM\x04`) 순수 파이썬 해제(상한 16 MB) → 버전 17/23/26/30/31 파일 메트릭·트레이스 체인·파일 이름 문자열·볼륨 테이블(이름·생성 시각·VSN·디렉터리 문자열) 디코드 → Prefetch 행에 `run_count`, `last_run_times[8]`, `volumes[]`, `referenced_files[]`(상한 1,000), `source_offset`. 기존 "압축 제한" 플래그 제거.
- `execution.runcount_spike`·`execution.suspicious_path` 규칙이 새 열을 읽도록 확인, 픽스처 갱신.
- 이벤트 로그 채널 서브노드: `domains.ts` eventlog 도메인에 채널 필터 링크(`cf=channel:...` 또는 `artifact_type` + 채널 파라미터 — 서버 필터가 `channel`을 지원하지 않으면 `artifact_filter.py`에 `channel=` 추가) — 보안·시스템·응용 프로그램·PowerShell(Operational·4104)·Windows Defender·방화벽·작업 스케줄러·서비스·스토리지(Storage-ClassPnP/NTFS)·사용자 PNP·Office Alerts·RDP(TerminalServices-*). `/tree`에 채널별 건수.

### 3.3 O3 — NTFS 타임스탬프 불일치·$LogFile + 카빙 확장 (`core/ntfs_metadata.py`, `core/carving.py`, `analysis_kinds.py`, `domains.ts`)
- 타임스탬프 불일치: ntfs-meta 분석 결과에 `timestamp-mismatch` 행(파일·MFT 번호·SI 4·FN 4·사유: SI<FN 생성, 나노초 0, FN>SI 수정, 미래 시각) 생성; 파일시스템 도메인 노드 "타임스탬프 불일치"(분석 노드 → 결과 보기), 기존 `ntfs.si_before_fn` 지표와 상호 링크. $LogFile: RCRD 페이지·LSN·redo/undo op 코드 바운디드 파싱 → `logfile-transaction`(LSN·시각 추정·op·대상 MFT·파일명 후보) 노드.
- 카빙: 시그니처 추가 — wav(RIFF/WAVE)·mp3(ID3/프레임 동기)·m4a/mp4(ftyp)·docx/xlsx/pptx(zip + `[Content_Types].xml` 검증)·hwp(OLE `HWP Document File`)·hwpx(zip + `Contents/`)·eml(헤더 패턴)·pe(MZ/PE, 섹션 테이블 검증)·evtx(ElfFile). 각 검증기와 최대 길이. 카빙 결과를 `windows-filesystem`·`media-*`·`generic-documents` 계열에 `recovery_method=carved` 행으로 통합(분석 결과 → 계열 노드 "복구됨" 필터), 뷰어 꼬리 섹션에 "복구 방법 카빙 · 오프셋".
