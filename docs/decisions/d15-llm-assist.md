# D15 — 제품 안의 LLM 사용 (개정)

상태: 결정(개정) · 대상: R8 / R9

## 배경

변호사와 감정인은 검색 문법을 모르고, AI 세션 한 건에 메시지가 수백 개 있다. 요약·번역·질의 변환에 생성 모델이 도움이 될 수 있다는 요구가 있다. 한편 이 제품의 화면은 증거를 다루므로 틀린 사실을 말하면 안 된다. 상대방 감정인은 "이 문장은 누가 썼고, 다시 만들면 같은가"를 물을 수 있다. 이전 결정은 "넣지 않음" 한 줄뿐이어서 사유, 도입 조건, 경로가 남아 있지 않았다. 이 문서가 그 근거를 기록한다.

## 결정

- R8에는 LLM을 넣지 않는다. R8은 결정적 보조 셋만 만든다.
- R9에 "로컬 전용 · 옵트인 · 인용 강제" 보조 계층을 도입한다. 순서는 질의 변환, 번역, 인용 요약, 초안이다. 각 쓰임새는 평가 게이트를 넘을 때만 출시한다. 못 넘으면 그 쓰임새는 출시하지 않는다.
- 자동 분류, AI 점수, 클라우드 LLM 기본 제공은 하지 않는다.

## 쓰임새별 판단

| 쓰임새 | 가치 | 위험 | 결정 |
|---|---|---|---|
| 한국어 자연어에서 검색 문법으로 | 높음 | 낮음. 출력은 사용자가 보고 고치는 질의이며 증거에 들어가지 않는다 | R8: 결정적 질의 도우미. R9: 로컬 LLM 1순위 |
| 선택 텍스트 번역(영·일·중에서 한국어) | 중 | 중. 오역이 판단에 영향을 준다. "기계 번역" 표시와 원문 병기로 통제 | R9 2순위 |
| 대화·AI 세션 요약 | 높음 | 높음. 환각, 그리고 증거 본문 속 지시문(프롬프트 주입) | R8: LLM 없는 추출 요약 카드. R9 3순위: 인용 강제 + 검증기 통과분만 |
| 특이사항 설명 | 중 | 낮음 | LLM 불필요. 규칙의 근거 문장에 증거 값을 채운다 |
| 사건 브리프·보고서 초안 | 높음 | 매우 높음. 감정서 문장의 작성 책임, 환각이 법정까지 감 | R9 후반 4순위. 태그된 항목만 입력, "초안" 칸, 검사관 수정 없이는 내보내기 불가. 감정서 템플릿에는 넣지 않는다 |
| 관련성·특권 자동 분류, AI 점수 | - | 판단을 대신하며 설명 불가 | 하지 않는다 |
| 클라우드 LLM | - | 증거·의뢰인 비밀의 외부 유출(비밀유지 의무, 개인정보 위탁·국외 이전, 압수물 범위) | 기본 기능으로 만들지 않는다 |

## R8 범위: 결정적 보조 3종

생성 모델 없이 고정 틀과 집계만으로 만든다. 같은 입력이면 항상 같은 출력이다.

1. 추출 요약 카드(세션): 첫 사용자 요청, 기간, 메시지·도구 호출 수, 도구 호출 상위, 건드린 파일 상위, 파괴적 호출, 절단·상한 표시. 수치는 세션 행의 카운터와 일치해야 하며 문장은 틀 고정이다.
2. 질의 도우미: 한국어 조건 칩을 검색 문법으로 바꾸고, 만든 질의를 그대로 보여 준다. 사용자가 고칠 수 있다.
3. 규칙 근거 문장: 규칙의 근거·오탐 문장에 증거 값을 채워 보여 준다.

## R8에 넣지 않는 이유

1. R8의 주제는 화면이 틀린 사실을 말하지 않게 하는 것이다. 안정된 인용 ID, 감사 기록, 가림 해제 흐름, 실데이터 기준선이 끝나기 전에 생성 계층을 얹으면 오류 출처가 하나 더 는다.
2. 로펌 PC는 GPU가 없는 경우가 많다. CPU에서 도는 소형 모델의 한국어 법률·기술 문장 품질은 평가 세트 없이 약속할 수 없다.
3. 모델 해시, 시드, 입력 해시 같은 재현·방어 장치가 아직 없다.
4. 조직이 승인한 외부 에이전트는 JSON 출력 경로로 제품 밖에서 같은 일을 할 수 있다. 책임 경계가 제품 밖으로 분명해진다.

## R9 단계 계획

- 순서: 질의 변환, 번역, 인용 요약, 초안. 앞 단계가 게이트를 넘어야 다음 단계로 간다.
- 로컬 전용: OpenAI 호환 로컬 엔드포인트(운영자가 설치)에만 연결한다. 주소가 루프백(127.0.0.1, ::1)이 아니면 거부한다. 모델은 번들하지 않는다.
- 옵트인: 기본 꺼짐. 사건 단위로 켜고 켠 사실을 감사에 기록한다.
- 인용 강제: 요약·초안의 문장마다 인용 ID를 붙인다. 검증기가 (1) ID가 실제 행인지, (2) 문장의 수치·시각·경로가 그 행에 있는지 확인한다. 통과하지 못한 문장은 버리거나 "근거 없음"으로 표시한다.

## 평가 게이트

한국어 골든 세트(합성 사건 50세션, 질의 100개)로 측정한다. 하나라도 못 넘으면 해당 쓰임새는 출시하지 않는다.

| 항목 | 통과선 |
|---|---|
| 질의 변환 정확도 | 90% 이상 |
| 요약의 근거 없는 문장 | 1% 이하 |
| 인용 정밀도 | 98% 이상 |
| 응답 시간(CPU 전용 PC) | 30초 이하 |

## 가드레일

1. 로컬 전용: 루프백이 아닌 주소는 거부한다.
2. 출력 분리: 보조 출력은 케이스 DB의 별도 표에 둔다. 증거 행, 특이사항, 검토 태그, 보고서 본문에 자동으로 기록하지 않는다. 화면과 내보내기에 "AI 보조 초안 — 증거 아님"을 표시한다. 검사관이 채택하면 검사관 메모로 복사되고 출처 표시가 남는다.
3. 인용 강제: 위 검증기를 통과한 문장만 표시한다.
4. 재현 기록: 모델 이름·파일 해시, 프롬프트 틀 버전, 입력 행 ID·해시, 매개변수(온도 0, 시드), 출력 해시, 사용자, 시각을 감사에 남긴다.
5. 주입 방어: 증거 텍스트는 신뢰하지 않는 데이터다. 보조 LLM에는 도구·행동 권한을 주지 않고(출력만), 출력 스키마를 고정한다. 증거 텍스트 속 지시는 권한을 만들지 못한다.
6. 가림 우선: LLM 입력에는 가림이 적용된 본만 넣는다. 해제본은 넣지 않는다.
7. 평가 게이트: 위 통과선을 넘은 쓰임새만 출시한다.

법률 검토를 R9 착수 전에 선행한다. 항목은 변호사 비밀유지 의무, 개인정보 처리(위탁·국외 이전), 압수·임의제출 범위와 관련성, 감정서 작성 책임, 변호사 단체의 생성형 AI 지침이다. 제품 문구에는 법령 조항을 넣지 않는다.

## 하지 않는 것

- 관련성·특권 등의 자동 분류, AI 점수.
- 클라우드 LLM의 기본 제공. 조직 설정과 계약 근거가 있을 때를 위한 확장 지점만 남기며, 그것도 법률 검토 이후다.
- 감정서 템플릿에 생성 문장을 넣는 것.

## 결과

- R8 화면의 모든 문장은 고정 틀과 증거 값에서 나오므로 재현 가능하고 설명 가능하다.
- 사용자는 R8에서 자연어 요약·번역을 얻지 못한다. 결정적 요약 카드와 질의 칩으로 대신한다.
- R9의 각 쓰임새는 독립 출시 대상이며, 게이트를 못 넘으면 출시가 연기될 수 있다.
- 보조 출력 전용 표와 감사 항목이 R9에서 필요해진다.

## 재검토 조건

- 골든 세트에서 모든 게이트를 넘는 로컬 모델이 CPU 전용 PC에서 확인될 때.
- 법률 검토에서 클라우드 LLM 사용의 계약·법적 근거가 정리되었을 때.
- 조직이 승인한 외부 에이전트 경로만으로는 사용자 요구를 충족하지 못한다는 증거가 쌓일 때.
- 인용 ID, 감사 기록, 가림 해제 흐름의 안정성이 실데이터 기준선에서 확인되기 전에는 재검토하지 않는다.
